# 17. 후기 · 포인트 설계 (확정 2026-10-25, 구현됨)

> 2026-10-25 사용자 요청. 이 문서를 확인받은 뒤 구현한다 (CLAUDE.md §5 "큰 작업은 계획 먼저").
> 확인이 필요한 결정은 §9에 모았다.

## 1. 한 줄 요약

일정에 넣은 장소(숙소·맛집·카페·쇼핑·관광·액티비티)마다 **종류별 별점 + 기타 한마디** 후기를 남긴다.
후기는 **로그인한 모든 사용자가 같은 장소에서 볼 수 있고**, 쓴 사람에게는 **포인트**가 쌓인다.
포인트와 후기는 **홈 서버에 계정별로** 저장한다. 닉네임은 가릴 수 있다(`User#N`).

## 2. 화면

### 2.1 후기 쓰기 — 일정 상세 시트

```
┌──────────────────────────────────────────┐
│ 이치란 신주쿠             [✎ 후기 입력]   │  ← 이름 오른쪽 (사용자 요청)
│ 1일차 · 10.24 (토)        방문 09:30 ⏱   │  ← 방문 시간 빠른 입력은 한 줄 아래로 (§9-1)
│ [길찾기] [주소 복사] [지도] [편집]        │
│ ── 후기 ─────────────────────────────── │
│ ★ 4.3 (12)  맛 4.6 · 가격 3.9 · 서비스 4.1│  ← 다른 사람 후기 요약
│ 김진하 · 2026.10.24  ★★★★★              │
│ "줄은 길지만 회전이 빨라요"               │
│ User#37 · 2026.10.20 ★★★★☆               │
│ [후기 더 보기]                            │
└──────────────────────────────────────────┘
```

- 이미 쓴 후기가 있으면 버튼이 **[✎ 내 후기]** (고치기·지우기)
- 보기 전용으로 공유받은 여행도 후기는 쓸 수 있다 (여행 내용을 바꾸는 게 아니므로) — §9-4
- 이동·메모 일정은 후기 버튼이 없다

### 2.2 후기 입력 시트 (종류별 템플릿)

```
┌──────────────────────────────────────────┐
│ 이치란 신주쿠 후기                         │
│ 종합      ★★★★★   (필수)                 │
│ 맛        ★★★★☆                          │
│ 가격      ★★★☆☆                          │
│ 서비스    ★★★★☆                          │
│ 분위기    ☆☆☆☆☆   (안 매겨도 됨)          │
│ 청결      ☆☆☆☆☆                          │
│ 기타 ┌─────────────────────────────────┐ │
│      │ 줄은 길지만 회전이 빨라요        │ │  최대 500자
│      └─────────────────────────────────┘ │
│ 공개: 닉네임 "김진하"로 보여요 (설정에서 가리기) │
│                    [후기 올리기 · +10P]   │
└──────────────────────────────────────────┘
```

- 별: 1~5, 탭으로 고름(다시 누르면 지움). **종합만 필수**, 나머지는 선택
- 시트를 닫아도 쓰던 내용은 이 기기에 남는다(초안)

### 2.3 종류별 항목

| 일정 종류 | 항목 (종합은 공통·필수) |
|---|---|
| 숙소 | 종합, 위치, 위생(청결), 가격, 시설, 서비스 |
| 맛집 | 종합, 맛, 가격, 서비스, 분위기, 청결 |
| 카페 | 종합, 맛(음료·디저트), 분위기, 가격, 좌석·편안함 |
| 쇼핑 | 종합, 가격, 상품 구성, 서비스, 접근성 |
| 관광 | 종합, 볼거리, 혼잡도(덜 붐빌수록 ★), 가격, 접근성 |
| 액티비티 | 종합, 재미, 가격, 안전·진행, 접근성 |

- 항목 목록은 `packages/shared`에 상수로 (웹·서버 같은 목록으로 검사). 나중에 항목을 더해도 옛 후기는 그대로 보인다

### 2.4 마이 화면 — 이름 오른쪽 포인트

```
김진하 ✎                     카카오
                             ● 동기화됨
🅟 120P                       ← 포인트 (누르면 적립 내역)
```

- 포인트를 누르면 **적립 내역** 시트: "이치란 신주쿠 후기 +10P · 10.24", "후기 지움 −10P"
- **내 후기 모아 보기**(마이 → 여행 도구) — §9-6

### 2.5 설정 — 닉네임 가리기

- 설정 → 개인정보 묶음에 스위치 **"후기에서 닉네임 가리기"**
- 켜면 다른 사람에게 `User#37`처럼 보인다. **이미 쓴 후기에도 바로 적용**(보여 줄 때 바꾸므로)
- 내 화면에서는 내 후기에 "나"라고 보인다
- `N`은 가입 순서대로 매기는 고정 번호(바뀌지 않음). 닉네임·계정 id를 추측할 수 없다

## 3. 같은 장소 판단 (후기를 모으는 열쇠)

후기는 **장소 키**로 모은다. 일정의 `place`에서 만든다:

| 출처 | 장소 키 | 비고 |
|---|---|---|
| Google | `g:<placeId>` | Google 약관상 place id는 저장 허용 |
| 카카오 | `k:<카카오 장소 id>` | 검색 결과 `place_url` 끝의 id |
| 네이버 | `n:<이름>|<좌표 소수 4자리>` | 네이버 지역검색은 고유 id가 없음 |
| 직접 입력(검색 안 함) | — | **후기 불가**: "장소를 검색해 고르면 후기를 쓸 수 있어요" (§9-2) |

- 같은 가게가 Google·카카오에 따로 있으면 처음에는 따로 모인다. 나중에 이름+좌표 50m 안이면 합쳐 보여 주는 단계를 둘 수 있다(이번 범위 밖)
- 서버에 보내는 것: 장소 키·장소 이름·종류·별점·글·방문 날짜. **사용자 위치·여행 내용은 보내지 않는다**

## 4. 포인트 규칙 (사용자 결정 2026-10-25)

| 행동 | 포인트 |
|---|---|
| **장소에 연결된** 후기 올리기 | **+100P** |
| 장소 연결 없이(직접 입력한 일정) 올리기 | 0P — 나중에 연결하면 그때 +100P |
| 후기 지움 / 운영자 숨김 | 그 장소로 받은 만큼 − |
| 같은 장소 다시 쓰기·고치기 | 추가 없음 (장소당 1번) |

- 직접 입력한 일정도 후기를 쓸 수 있다. 후기 창에서 구글·네이버(카카오)로 같은 장소를 찾아 연결하도록 안내하고, 연결하면 일정에도 장소가 붙는다
- 어뷰징 막기: 장소당 1번, 하루 10곳까지, 다녀온 일정(날짜 ≤ 오늘)만, 쓰기 분당 10회
- 포인트는 쌓이기만 한다. 현금 가치·교환 없음

## 5. 서버 (홈 서버 SQLite, 마이그레이션 14)

```sql
ALTER TABLE users ADD COLUMN public_no INTEGER;          -- User#N (가입 순, 기존 사용자는 created_at 순으로 채움)
ALTER TABLE users ADD COLUMN hide_nickname INTEGER NOT NULL DEFAULT 0;
CREATE UNIQUE INDEX users_public_no ON users(public_no);

CREATE TABLE reviews (
  id TEXT PRIMARY KEY,                -- uuidv7
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  place_key TEXT NOT NULL,
  place_name TEXT NOT NULL,
  kind TEXT NOT NULL,                 -- lodging | food | cafe | shopping | place | activity
  ratings TEXT NOT NULL,              -- JSON {"overall":5,"taste":4,...}
  note TEXT,                          -- 기타 (500자)
  visited_on TEXT,                    -- YYYY-MM-DD (일정 날짜)
  hidden INTEGER NOT NULL DEFAULT 0,  -- 관리자 숨김
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE (user_id, place_key)
);
CREATE INDEX reviews_place ON reviews(place_key, hidden, created_at);

CREATE TABLE point_ledger (           -- 적립·회수 기록 (잔액 = 합계, 고치지 않고 쌓기만)
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  delta INTEGER NOT NULL,
  reason TEXT NOT NULL,               -- review | review_bonus | review_deleted | admin_hidden
  review_id TEXT,
  created_at TEXT NOT NULL
);
CREATE INDEX point_ledger_user ON point_ledger(user_id, created_at);
```

- 포인트는 **서버만** 계산·기록한다(기기에서 보낸 숫자를 믿지 않음). 후기 저장과 포인트 기록은 한 트랜잭션
- 탈퇴하면 후기·포인트도 지운다(ON DELETE CASCADE) — §9-5

### 5.1 API (모두 `requireUser`, 요청 제한)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/reviews?place=<키>&cursor=` | 그 장소 후기 목록(최신순 20개) + 요약(평균·항목별 평균·개수). 이름은 닉네임 또는 `User#N` |
| GET | `/api/reviews/mine` | 내 후기 목록 |
| PUT | `/api/reviews` | 내 후기 쓰기·고치기 (장소 키당 1개) → `{ review, pointsAwarded, balance }` |
| DELETE | `/api/reviews/:id` | 내 후기 지우기 (포인트 회수) |
| GET | `/api/me/points` | 잔액 + 최근 적립 내역 |
| PATCH | `/api/me` | `{ hideNickname: boolean }` 추가 |
| POST | `/api/admin/reviews/:id/hide` | 관리자 숨김 |

- 검사(Zod, `packages/shared`): 별점 1~5 정수, 종류별 허용 항목만, 글 500자, 장소 키 형식
- 요청 제한: 쓰기 10회/분, 읽기 60회/분
- 외부 API 호출 없음 → API 사용량·과금 영향 없음

## 6. 기기(웹)

- 장소별 후기는 **열 때 서버에서 받아** 보여 주고, 최근 본 것은 기기에 잠시 저장(오프라인에서도 마지막 본 후기)
- **오프라인에서 쓴 후기**: 기기 대기열(Dexie `pendingReviews`)에 두고, 연결되면 올림 → 그때 포인트 적립. 화면에 "연결되면 올려요" 표시
- 내 포인트 잔액은 마지막 받은 값을 기기에 저장해 마이 화면에 바로 보임
- 백업 JSON(`schemaVersion`)에는 넣지 않는다 — 서버 데이터(계정에 붙음). 하위 호환 영향 없음
- 지연 로딩: 후기 시트·목록은 처음 열 때 불러온다(첫 화면 크기 영향 거의 없음)

## 7. 개인정보·약관

- 공개 범위: **이 앱에 로그인한 사람만** (앱 전체가 로그인 필요). 보기 전용 공유 링크(`/api/public/*`)에는 후기를 싣지 않는다
- 보이는 정보: 닉네임(또는 User#N)·등록 날짜·별점·글. 여행 이름·일정·위치는 보이지 않음
- Google 장소에 우리 후기를 보여 주는 것은 우리 사용자 글이라 괜찮다. 단 **Google 평점·리뷰와 섞어 평균 내지 않는다**(Google 데이터는 저장 금지 — docs/10 §2.1)
- 개인정보 처리방침(`legal/content.ko.ts`)에 "후기·포인트" 항목 추가

## 8. 단계 (확인 후)

1. 공용 스키마·템플릿 상수 + 서버 마이그레이션 14·API·테스트(인가 누락 포함)
2. 일정 상세 [후기 입력] 버튼 + 입력 시트 + 오프라인 대기열
3. 일정 상세 후기 목록·요약
4. 마이 포인트·적립 내역, 설정 닉네임 가리기
5. 관리자 숨김, 개인정보 처리방침, 문서

## 9. 결정 (2026-10-25 사용자)

1. 상세 시트 머리글: 이름 오른쪽 [후기 입력], 그 아래 방문 시간 (추천안)
2. 직접 입력한 일정도 후기 허용 — 장소 연결을 안내, **연결해야 포인트·공개**
3. 포인트: 연결된 후기 1곳 **+100P** (보너스 없음), 하루 10곳
4. **보기 전용 공유받은 사람은 후기 불가** (서버 403, 화면에 버튼 없음)
5. 탈퇴: 후기는 지우지 않고 작성자만 **User#N**으로 (reviews.user_id → NULL, author_no 보관). 포인트 기록은 삭제
6. 내 후기 모아 보기: 마이 → 여행 도구 → 내 후기 (`/me/reviews`)
7. 다녀온 뒤에만 쓰기 (추천안)

## 10. 영업시간 (같은 날 결정)

- 카카오·네이버 API는 영업시간을 주지 않는다. Google 상세만 가능(Enterprise 등급, 무료 월 1,000회)
- 사용자 결정: 지금처럼 **누를 때만** 불러오기. "불러온 정보 저장"은 **Google 약관상 불가**(place id 외 저장 금지 — docs/10 §2.1)라 보류, 사용자에게 알림
