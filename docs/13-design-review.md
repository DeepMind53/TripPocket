## 1. 요약 — 가장 중요한 7가지
| # | 항목 | 왜 중요한가 | 조치 |
|---|---|---|---|
| 1 🔴 | **앱 이름·도메인 확정** | 브라우저 저장 데이터·OAuth 콜백·지도 키 제한·공유 링크가 모두 도메인에 묶임. 나중에 바꾸면 사용자 데이터 접근 불가 | A1 결정 → 도메인 구매(Cloudflare) |
| 2 🔴 | **가입 정책 (초대제 vs 누구나)** | 홈 PC 부하, 보안 책임, 개인정보처리방침·약관 범위, Google API 비용이 모두 달라짐 | G1 |
| 3 🔴 | **소셜 로그인 운영 요건** | 네이버 로그인은 일반 사용자 공개 전 **검수** 필요, 카카오는 이메일 등 받으려면 비즈 앱 전환 필요, Google은 OAuth 동의 화면 게시(외부 사용자) 필요 — 일정에 영향 | G2: 1차 제공자 1개로 시작 |
| 4 🔴 | **클라이언트–서버 버전 호환** | PWA는 옛 버전이 캐시로 오래 살아남음 → 서버 API가 바뀌면 옛 앱이 깨짐 | `/api/v1` 버전 고정 + 응답 헤더 `X-Min-Client-Version` → 낮으면 "업데이트" 안내 (아래 3.2) |
| 5 🟡 | **Google 약관 재확인** | 비Google 지도 위 표시 금지, 캐싱 제한, 출처 표시 — 위반 시 키 정지 위험 | 개발 착수 전 원문 확인 후 `10` 문서 확정 |
| 6 🟡 | **개발 중 API 비용** | 개발·테스트 중 Places 호출이 과금 SKU에서 빠르게 소진 | 서버에 `PLACES_MODE=fixture` (녹화된 응답 사용) 기본, 실제 호출은 명시적으로만 |
| 7 🟡 | **홈 PC 단일 장애점** | 정전·윈도우 업데이트 재부팅·디스크 고장 | 로컬 우선 구조로 영향 최소화 + 백업·모니터링 (`09` §7.4~7.5) + 복구 리허설 |

## 2. 기능 관점 점검
| 영역 | 빠진 것 / 애매한 것 | 보완 제안 | 등급 |
|---|---|---|---|
| 여행 만들기 | "날짜 미정" 여행 처리 | 날짜 없이 만들면 '가고 싶은 곳'만 있는 여행 → 날짜 정하면 Day 생성 | 🟡 J1 |
| 여행 만들기 | 도시 → 타임존·통화·국가 매핑 데이터 | 주요 도시 100개 정적 JSON(`packages/shared/data/cities.json`) + 직접 입력 시 지도 지오코딩 | 🟡 |
| 일정 | 항공 일정의 타임존 자동 설정 | 공항 코드 → 타임존 정적 데이터(주요 공항) or 사용자 선택 | 🟡 J2 |
| 일정 | 자정 넘는 일정(야간 버스, 밤 비행) | `endDate` 필드 추가 or endTime < startTime이면 다음날로 해석 | 🟡 |

| 장소 | 영업시간과 일정 시간 충돌 경고 | "이 시간엔 문을 닫아요" 표시 (상세 조회 시에만) | 🟢 P2 |
| 예약 | 예약 메일·PDF 붙여넣기 | P2 유지 | 🟢 |
| 준비 | 국가별 필수 항목(전압·플러그 등) | 템플릿에 "국가 팁" 1줄 (정적 데이터) | 🟢 |

| 알림 | 출발 전날·체크인 알림 | iOS는 홈 화면 설치 PWA에서만 웹 푸시 가능, 서버 푸시 필요 → P2 | 🟢 |

## 3. 기술 관점 점검
### 3.1 개발 환경
| 항목 | 내용 | 등급 |
|---|---|---|
| 로컬 HTTPS | 위치 권한·Service Worker·`__Host-` 쿠키는 보안 컨텍스트 필요 — `localhost`는 예외로 허용되나, **휴대폰 실기기 테스트**는 HTTPS 필요 → Cloudflare Tunnel 개발용 서브도메인 `dev-api.` 사용 | 🔴 |
| OAuth 개발 콜백 | 각 제공자 콘솔에 개발/운영 콜백 URL 둘 다 등록 | 🟡 |
| 환경 분리 | `development` / `production` 2개. `.env.example`에 모든 키 나열, 기동 시 Zod 검증 | 🔴 |
| 외부 API 모킹 | Places·네이버·수출입은행 응답 fixture + MSW(웹) | 🟡 |
| 시드 데이터 | `pnpm seed`로 샘플 여행(도쿄 4박 5일, 제주 2박 3일) 생성 → 화면 개발·스크린샷용 | 🟡 |
| 패키지 매니저 | pnpm 미설치 → `corepack enable` | 🟡 B7 |

### 3.2 API 호환·배포
| 항목 | 제안 |
|---|---|
| API 버전 | 경로 `/api/v1/...` (문서 내 `/api/...`는 v1을 의미) |
| 최소 클라이언트 버전 | 서버 응답 헤더 `X-Min-Client-Version`. 웹앱이 더 낮으면 "새 버전으로 업데이트해 주세요 [업데이트]" (SW 갱신) |
| 동기화 스키마 버전 | push 요청에 `schemaVersion` 포함 → 서버는 아는 범위만 수용, 모르는 필드는 보존(JSON 저장 이점) |
| 서버 배포 | `ops/deploy.ps1`: git pull → pnpm install --frozen-lockfile → build → DB 백업 → 마이그레이션 → 서비스 재시작 → `/healthz` 확인, 실패 시 롤백 |
| 웹 배포 | main 머지 → GitHub Actions → Cloudflare Pages 자동 |
| DB 마이그레이션 | 서버: Drizzle migrate, **배포 전 자동 백업** 필수 |

### 3.3 동기화 세부
| 항목 | 보완 |
|---|---|
| 첨부 동기화 | 메타데이터는 sync, 파일 본문은 별도 업로드 큐(재시도, Wi-Fi 설정 반영) |
| 같은 기기 다른 계정 | 로그인 계정이 바뀌면 로컬 DB를 계정별로 분리(`travel-planner-<accountId>`) or 로그아웃 시 정리 강제 ⚠️ G5 |
| 공유 여행 멤버 탈퇴 | 소유자 탈퇴 시 여행 소유권 이전 or 함께 삭제 정책 ⚠️ G6 |
| 시계 오차 | LWW 판정은 **서버 수신 순서(rev)** 기준, 클라이언트 `updatedAt`은 표시용 — `09` §6.3 문구 수정 필요 ✅(아래 반영) |
| 대량 첫 동기화 | 페이지네이션(500건), 진행률 표시 |

### 3.4 보안 추가 점검
| 항목 | 보완 |
|---|---|
| 공유 링크 `/s/:id` | 추측 불가 ID(128bit), `noindex` 메타, 민감정보 기본 제외, 조회 rate limit, 끄면 즉시 404 |
| 관리자 기능 | 초대제면 승인 관리 필요 → 별도 웹 UI 대신 **로컬 CLI**(`pnpm admin approve <email>`) — 관리 화면을 인터넷에 노출하지 않음 |
| 계정 연결 | 같은 사람이 네이버·구글로 각각 로그인 → 별도 계정. 계정 연결은 P2 (이메일 자동 병합 금지 — 탈취 위험) |
| 백업 암호화 키 | 키 분실 = 백업 무용 → 키를 오프라인(종이/비밀번호 관리자)에 보관, 복구 리허설에 포함 |
| 의존성 공급망 | lockfile + `pnpm audit` + 설치 스크립트 제한(`onlyBuiltDependencies`) |
| 로그 보존 | 접근 로그 30일, IP는 앞 3옥텟만 |

### 3.5 성능
- 지도 SDK(구글·네이버)는 각각 수백 KB → 지도 화면 진입 시에만 로드, 둘 다 동시에 로드하지 않음
- 첫 화면(홈·일정 목록)은 지도 없이 렌더 → 지도는 뒤이어 표시
- Pretendard 서브셋 + `font-display: swap`

## 5. 문서 간 불일치 정리 (이번 점검에서 수정)

|---|---|---|
