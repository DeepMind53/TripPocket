## 3. A. 입력 보호 — 쓰던 내용을 잃지 않게

### A1 (P1) 입력 시트가 묻지 않고 닫힌다

- **근거**: `shared/ui/BottomSheetImpl.tsx` — 아래로 40px 끌면 `onOpenChange(false)`, 바깥 누름은 알림(토스트)만 예외.
  저장 안 한 변경 확인은 `ChecklistPage`에만 있다
- **기준**: ui-ux-pro-max `sheet-dismiss-confirm`(저장 안 한 변경이 있으면 닫기 전에 확인), `form-autosave`, impeccable harden "입력 손실"

- **결정 (2026-11-23, §9 Q8 ①: 확인 창만)**
  1. 시트에 `dirty`(처음 연 값과 지금 값이 다름) 표시를 넘기는 공통 방법을 만든다 — `BottomSheet`에 `confirmClose?: boolean`
  2. `dirty`일 때 닫으려 하면 기존 확인 창(`ConfirmHost`)을 띄운다: 제목 "입력한 내용을 버릴까요?" / 설명 "버리면 되돌릴 수 없어요" / [계속 입력] [버리기(빨강)] (새 문구 키 4개)

- **대상**: `ItemFormSheet`, `BookingFormSheet`, 여행 설정, 개인정보 항목 입력, 후기 입력 (입력칸이 있는 시트 전부 — 구현 때 목록 확정)

## 4. B. 알림·가림 — 중요한 버튼이 가려지지 않게

### B1 (P1) 알림이 겹쳐 쌓이고 버튼을 가린다
- **지금**: 일정 3개를 연달아 추가하면 "일정을 추가했어요"가 2~3개 쌓여 화면 아래 1/4을 덮고 ⚡ 버튼을 가린다 (스크린샷 04).
  알림이 남아 있는 채로 일정 상세를 열면 시트 아래 [다른 날로 이동]·[삭제] 바로 위를 덮는다 (스크린샷 05)
- **근거**: `toastStore.ts` — 최근 3개까지 그대로 쌓음(같은 문구도 따로), 시트가 열려도 그대로
- **기준**: ui-ux-pro-max `toast-dismiss`, `focus-not-obscured`(떠 있는 UI가 누를 곳을 가리면 안 됨), `fixed-element-offset`
- **설계** (기능 변화 없음, 질문 없이 확정)
  1. **같은 문구는 하나로**: 이미 떠 있으면 새로 쌓지 않고 시간만 다시 센다
  2. **한 번에 하나**: 새 알림이 오면 앞의 것은 바로 닫는다. 단 [실행 취소]가 있는 알림은 다른 알림에 밀려 사라지지 않게 남은 시간 동안 우선
  3. **시트가 열리면** 이미 떠 있던 일반 알림은 닫고, 시트 안에서 생긴 알림은 시트의 저장 줄 위에 띄운다
  4. 화면에 ⚡ 버튼이 있으면 알림을 그 위로 띄운다 (겹치지 않게)

### B2 (P2) ⚡ 버튼이 목록 마지막 줄을 덮는다
- **지금**: 준비물 화면 맨 아래 '기타' 줄의 휴지통이 ⚡ 버튼 밑에 깔린다 (스크린샷 08). 마이 화면도 목록 오른쪽 화살표를 덮는다
- **기준**: `fixed-element-offset`, `scroll-behavior`
