## 3. A. 입력 보호 — 쓰던 내용을 잃지 않게

### A1 (P1) 입력 시트가 묻지 않고 닫힌다

- **기준**: ui-ux-pro-max `sheet-dismiss-confirm`(저장 안 한 변경이 있으면 닫기 전에 확인), `form-autosave`, impeccable harden "입력 손실"

## 4. B. 알림·가림 — 중요한 버튼이 가려지지 않게

- **근거**: `toastStore.ts` — 최근 3개까지 그대로 쌓음(같은 문구도 따로), 시트가 열려도 그대로
- **기준**: ui-ux-pro-max `toast-dismiss`, `focus-not-obscured`(떠 있는 UI가 누를 곳을 가리면 안 됨), `fixed-element-offset`
- **설계** (기능 변화 없음, 질문 없이 확정)
  1. **같은 문구는 하나로**: 이미 떠 있으면 새로 쌓지 않고 시간만 다시 센다
  2. **한 번에 하나**: 새 알림이 오면 앞의 것은 바로 닫는다. 단 [실행 취소]가 있는 알림은 다른 알림에 밀려 사라지지 않게 남은 시간 동안 우선
  3. **시트가 열리면** 이미 떠 있던 일반 알림은 닫고, 시트 안에서 생긴 알림은 시트의 저장 줄 위에 띄운다
  4. 화면에 ⚡ 버튼이 있으면 알림을 그 위로 띄운다 (겹치지 않게)

### R1 (P1) 휴대폰 뒤로 가기가 시트를 닫지 않는다
- **지금**: 일정 추가 시트를 열고 안드로이드 뒤로 가기(버튼·옆에서 미는 제스처)를 하면, 시트는 그대로 사라지고 **앞 화면으로 넘어간다**.
  첫 화면(홈)이었다면 **앱이 닫힌다**. 쓰던 내용은 묻지 않고 사라진다
- **근거**: `shared/ui/BottomSheetImpl.tsx`는 Radix Dialog — 바깥 누름·Esc·끌기만 받는다.
  `apps/web/src` 어디에도 `popstate`·`pushState`가 없어 뒤로 가기는 시트를 모르고 화면 기록을 한 칸 되돌린다
- **기준**: ui-ux-pro-max `gesture-nav-support`(안드로이드 뒤로 가기와 충돌 금지), `modal-escape`, `back-stack-integrity`(갑자기 홈으로 튀지 않기), `sheet-dismiss-confirm`
- **왜 중요**: 안드로이드 사람은 "닫기"를 뒤로 가기로 한다 (화면 위 [×]보다 먼저 손이 감). A1 확인 창을 만들어도 이 길은 그대로 뚫려 있다
- **결정 (2026-11-23, §11 Q10 ①: 시트만 닫기)**
  1. 시트가 열릴 때 화면 기록에 한 칸(`{ sheet: id }`)을 더 쌓는다. 주소는 바꾸지 않는다
  2. 뒤로 가기 → 그 칸이 빠지면서 시트만 닫힌다 (화면은 그대로)
  3. 입력이 바뀐 시트(A1의 `dirty`)면 바로 닫지 않고 A1 확인 창 — [계속 입력]이면 칸을 다시 쌓는다
  4. [×]·바깥 누름·저장으로 닫히면 쌓은 칸을 조용히 뺀다 (`history.back()`, 이때는 시트를 다시 닫지 않게 표시)
  5. 시트 위 시트(예: 일정 추가 위 장소 고르기)는 한 칸씩 — 뒤로 한 번에 위 시트 하나만 닫힌다
  6. 한 곳(`BottomSheet` 부품)에서 처리해 모든 시트가 같은 규칙. 아이폰은 뒤로 가기 버튼이 없어 변화 없음
- **테스트**: e2e "시트 열기 → `page.goBack()` → 시트만 닫히고 주소 그대로", "입력 후 뒤로 → 확인 창"
- **조심**: 화면 이동(`TopBar` 뒤로 버튼의 `history.state.idx`)과 섞이지 않게, 시트가 연 칸은 `idx`를 건드리지 않는다

### R2 (P2) 전광판 두 개가 같은 박자로 겹쳐 기온이 안 보임
- **지금**: 날짜 머리 오른쪽 칸은 [날씨 · 오늘 · Plan B]를 3초마다 번갈아 보이고(바깥 전광판),
  그 안의 날씨는 작년 기록일 때 [과거 날씨 ↔ 그림·기온]을 또 3초마다 번갈아 보인다(안쪽 전광판, 2026-11-23 c905073).
  두 전광판이 **같은 순간에 시작**하므로 Plan B가 있는 날은
  0초 바깥=날씨·안쪽="과거 날씨" → 3초 바깥=Plan B(안쪽은 숨어서 기온) → 6초 바깥=날씨·안쪽="과거 날씨" … **기온은 영원히 숨은 차례**
- 또 날씨는 화면이 뜬 뒤 늦게 도착할 때가 많아(`useTripWeather`), 그때 시작한 전광판은 "1일차 ↔ 날짜"와 박자가 어긋날 수 있다
- **근거**: `features/itinerary/DaySection.tsx:284` 바깥 `RollingSlot` 안에 `DayWeatherBadge`(안쪽 `RollingSlot`).
  `shared/ui/RollingSlot.tsx`는 칸마다 자기 타이머(`setInterval`)를 처음 보인 순간부터 따로 돈다
- **기준**: impeccable animate "움직임은 상태를 설명할 때만, 겹쳐 쌓지 않기", ui-ux-pro-max `excessive-motion`(한 화면에 움직이는 것 1~2개), `motion-consistency`(같은 박자)
- **설계**
  1. **공용 시계 하나**: 앱 전체가 3초짜리 시계 하나를 같이 본다 (`Math.floor(지금 / 3000)`). 모든 전광판이 같은 순간에 넘어가고, 늦게 뜬 칸도 박자가 맞는다. 타이머도 날짜 수만큼 → 1개
  2. **겹치지 않게 펼치기**: 바깥 전광판이 있는 자리(일정 날짜 머리)에서는 날씨를 따로 굴리지 않고 바깥 목록에 펼쳐 넣는다 —
     [과거 날씨 · 그림·기온 · 오늘 · Plan B] 중 있는 것만 차례로. 칸 폭은 가장 넓은 것에 고정(`reserve`)
  3. 바깥 전광판이 없는 곳(빈 날 줄·여행 모드)은 지금처럼 날씨 칸 혼자 번갈아
  4. 화면이 안 보이는 동안(다른 앱·화면 꺼짐)은 시계를 멈춘다 (`visibilitychange`) — 배터리
- **테스트**: 단위 "Plan B + 작년 기록 → 9초 안에 과거 날씨·기온·Plan B가 모두 한 번씩 보임", "늦게 붙은 칸도 같은 순간에 넘어감"

### R3 (P2) 움직임 줄이기를 켜도 전광판이 계속 바뀐다
- **지금**: 움직임 줄이기(휴대폰 접근성 설정)면 굴러 들어오는 효과만 빠지고, 글자는 3초마다 계속 바뀐다
- **근거**: `styles/index.css` `@media (prefers-reduced-motion)`에서 `.tp-roll` 시간만 1ms. 바꾸는 타이머는 그대로
- **기준**: WCAG 2.2.2 "저절로 5초 넘게 바뀌는 정보는 멈출 수 있어야", impeccable animate "움직임 줄이기 = 적고 부드럽게, 상태는 남기기", ui-ux-pro-max `reduced-motion`
- **왜 중요**: 움직임 줄이기를 켜는 사람은 대개 화면이 계속 바뀌면 어지럽거나 읽기 어려운 사람이다. 3초 안에 다 못 읽은 날짜·기온이 계속 넘어간다
- **결정 (2026-11-23, §11 Q11 ②: 6초로 느리게)**
  1. 움직임 줄이기면 공용 시계(R2)를 6초 박자로 — 모든 전광판이 함께 6초마다, 굴러 들어오는 효과 없이 바로 바뀜 (지금과 같음)
  2. 움직임 줄이기가 아니면 지금처럼 3초
  3. 화면 읽기 프로그램은 지금처럼 전부를 한 번에 읽는다
  - 참고: 저절로 바뀌는 것을 멈출 길은 여전히 없어 WCAG 2.2.2는 어긴 채 (사용자 결정으로 받아들임). 불편 의견이 생기면 '누르면 다음' 방식(①)을 다시 검토
- **테스트**: 단위 "움직임 줄이기 → 6초에 넘어감, 3초에는 그대로"

### R4 (P2) 한글 입력 중 Enter가 두 번 처리된다
- **지금**: PC·아이패드 키보드로 "김치"를 치고 Enter를 누르면 글자를 확정하는 Enter와 저장 Enter가 한꺼번에 처리돼,
  저장한 뒤 빈 칸에 마지막 글자 "치"가 남거나(못 먹는 음식 추가) 같은 장소가 두 번 저장될 수 있다
- **근거**: `onKeyDown={(e) => e.key === 'Enter' && …}`에 한글 조합 중 확인(`isComposing`)이 없다 —
  `features/common/SavedSpotsButtons.tsx:137`(내 장소 이름), `features/me/CustomFoodsField.tsx:67`·`:77`(못 먹는 음식 추가). `itinerary/DayNoteField.tsx:33`(Enter로 칸 닫기)도 같은 모양
- **기준**: ui-ux-pro-max `ime-composition-enter`(조합 확정 Enter와 제출 Enter를 나누기)
- **설계**: 공용 함수 `isSubmitEnter(e)` = Enter이면서 조합 중이 아님(`e.nativeEvent.isComposing`도 아니고 `keyCode 229`도 아님). 위 4곳을 모두 이 함수로.
  앞으로 Enter 처리는 이 함수만 쓰도록 `docs/conventions/coding-rules.md`에 한 줄
- **테스트**: 단위 "조합 중 Enter → 저장 안 함, 조합 끝난 Enter → 한 번 저장"

### R5 (P3) 오류 알림이 "못 했어요"에서 끝난다
