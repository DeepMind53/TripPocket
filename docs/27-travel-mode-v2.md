# 27. 여행 모드 개선 — 설계 제안

- 상태: **1~4단계 구현** (2026-11-04, 결정 Q1~Q5 아래). 5단계(웹 푸시)·E1·E2·C5는 아직
- 날짜: 2026-11-04
- 요청: 여행 모드를 **사용자 편의성** 위주로 더 낫게. UI·UX는 간단하게, **당일·현재 시각** 기준으로 여행 중에 도움이 되게
- 바탕: 1차 구현(docs/25, 실험실 `travelMode`, 2026-11-03) — 오늘/내일 탭, 지금·다음 카드, 남은 일정, 엄지 버튼, 햇빛 모드, 출발 10분 전 알림

## 1. 지금 모습과 아쉬운 점
| 지금 | 아쉬운 점 |
|---|---|
| 지금·다음 카드에 시각·남은 분 | "언제 나가야 하는지"를 사람이 계산한다 (이동 시간 없음) |
| 남은 일정 목록 전체 | 지난 일정도 섞여 길다. 다녀옴 표시만 있고 "건너뛰기"는 없다 |
| [오늘][내일] 탭 | 내일 탭은 오늘 밤에만 쓸모 있다 |
| 엄지 버튼 = 빠른 메뉴 바로가기 | 시간대와 상관없이 늘 같은 버튼 |
| 날씨 그림 하나 | 비 오는 시각·우산 같은 행동이 안 보인다 |
| 알림은 앱이 열려 있을 때만 | 휴대폰을 주머니에 넣으면 놓친다 |

## 2. 원칙 (1차와 같고, 하나 더)
- **3초 규칙**: 화면을 켜면 3초 안에 "지금 뭐 하지 · 언제 나가지 · 어떻게 가지"
- **버튼 하나 = 행동 하나**: 길찾기·다녀옴·건너뛰기처럼 바로 끝나는 것만
- **고치지 않는다**: 고칠 일이 생기면 [홈]으로 나가서
- **새로**: **시간에 따라 화면이 알아서 바뀐다** — 사용자가 고르지 않아도 아침·이동 중·저녁에 맞는 것이 위로

## 3. 아이디어 — 여러 관점

### A. 시간 관점 (하루 흐름)
| # | 아이디어 | 화면 |
|---|---|---|
| A1 | **하루 단계 자동 전환**: 아침(첫 일정 전) → 낮(일정 중) → 저녁(마지막 일정 뒤) | 맨 위 카드가 바뀐다 |
| A2 | **아침 브리핑 카드**: 오늘 일정 수·첫 출발 시각·날씨·준비물 한 줄 ("8:30 출발 · 오후 비 · 우산") | 첫 일정 전까지만 |
| A3 | **"나갈 시각" 표시**: 다음 일정 시각 − 이동 시간 − 여유 10분 → "10:20에 나가요" (남은 분보다 행동이 분명) | 다음 카드 큰 글씨 |
| A4 | **늦어짐 감지**: 일정 끝 시각이 지났는데 다녀옴이 없으면 "다음 일정 미룰까요? [15분][30분][건너뛰기]" — 그날만 시각을 밀어 보여 줌(저장 안 함) | 지금 카드 아래 한 줄 |
| A5 | **저녁 정리 카드**: 마지막 일정 뒤 "오늘 7곳 중 5곳 · 내일 첫 일정 9:00" + 숙소로 길찾기 | 내일 탭 대신 |
| A6 | **[내일] 탭 → "내일 미리보기" 한 줄**로 줄이고 탭은 없앤다 (저녁에만 펼침) | 탭 줄 제거 |

### B. 이동 관점
| # | 아이디어 | 화면 |
|---|---|---|
| B1 | **이동 시간 한 번 계산**: 다음 일정까지 도보/대중교통 시간 (이미 있는 경로 API 사용·캐시, 무료량 안에서) | 다음 카드 "지하철 18분" |
| B2 | **이동 중 카드**: 비행기·기차·버스·렌터카 시간대에는 그 표(편명·좌석·게이트·도착 시각)가 맨 위 | 지금 카드 자리 |
| B3 | **숙소로 길찾기 + 주소 크게 보기**: 택시 기사에게 보여 주는 현지어 주소 카드 (이미 있는 택시 카드 재사용) | 엄지 버튼 길게 누르기 |
| B4 | **마지막 교통 시각 안내**: 숙소 쪽 막차가 가까우면 "막차 23:40" (데이터 있을 때만, 없으면 표시 안 함) | 저녁 카드 |

### C. 한 손·밖에서 (UI)
| # | 아이디어 | 화면 |
|---|---|---|
| C1 | **엄지 버튼 4칸 고정 + 시간대별 자동**: 아침 = 숙소 체크아웃·날씨·준비물 / 낮 = 길찾기·위치 저장·환율 / 저녁 = 숙소로·택시 카드·예약번호. 나머지는 빠른 메뉴 | 아래 4칸 |
| C2 | **카드 밀어서 다녀옴/건너뛰기**: 남은 일정 줄을 오른쪽=다녀옴, 왼쪽=건너뛰기 (버튼도 함께, 실수하면 되돌리기) | 목록 |
| C3 | **지난 일정 접기**: "지난 일정 3개" 한 줄로 접고 남은 것만 | 목록 |
| C4 | **햇빛 모드 자동 제안**: 화면 밝기 최대·낮 시간이면 한 번 "햇빛 모드 켤까요?" (센서 권한 없이 시각만으로) | 머리 |
| C5 | **글씨 3단계**: 보통·크게·아주 크게 (부모님과 여행) | 설정 한 줄 |

### D. 안심 관점
| # | 아이디어 | 화면 |
|---|---|---|
| D1 | **긴급 버튼 상시**: 머리 오른쪽 🆘 (긴급 연락처 시트, 인터넷 없어도) | 머리 |
| D2 | **오늘 주의 한 줄**: 특보·안전공지·미세먼지·공휴일 휴무를 하나로 모아 가장 중요한 것만 | 날씨 줄 아래 |
| D3 | **오프라인 표시**: 인터넷이 끊기면 "오프라인 · 일정은 그대로 보여요" 작은 칩 | 머리 |

### E. 함께 여행 관점
| # | 아이디어 | 화면 |
|---|---|---|
| E1 | **오늘 일정 공유 한 번에**: 보기 전용 링크로 "오늘 일정"만 (이미 있는 공유 링크 재사용) | 엄지 버튼 후보 |
| E2 | **모이는 곳·시각**: 일정에 "모이기" 표시가 있으면 지금 카드에 크게 | 지금 카드 |

### F. 알림 관점
| # | 아이디어 | 비고 |
|---|---|---|
| F1 | **웹 푸시로 나갈 시각 알림** (앱이 닫혀 있어도): 이미 있는 푸시(docs/20 G1) 사용. 서버에는 "몇 시에 보낼지"만, 장소·좌표는 보내지 않음 | 서버 저장 규칙 확인 필요 |
| F2 | **알림 한 번만**: 같은 일정에 두 번 울리지 않게, 조용한 시간(22~07시) 없음 | |

## 4. 추천 화면 (간단하게 합친 안)
```
┌ [🏠]  3일차 · 11.07 (목)  14:05   ☀18°  [🆘] ┐  ← 홈=끄기(왼쪽), 긴급(오른쪽)
│ ⚠ 오후 4시부터 비 · 우산                       │  ← 오늘 주의 한 줄 (있을 때만)
├──────────────────────────────────────────┤
│ 지금  센소지 · 14:30까지                        │
│ ───────────────────────────────            │
│ 다음  도쿄타워 15:00                            │
│       14:35에 나가요 · 지하철 18분               │  ← "나갈 시각"이 가장 크게
│       [        길찾기        ]                  │
├──────────────────────────────────────────┤
│ 남은 일정 2  ▸ 지난 일정 3                       │
│  15:00 도쿄타워        [다녀옴]                  │
│  19:00 저녁 이자카야                             │
├──────────────────────────────────────────┤
│ [🛏 숙소로 길찾기] [📍 위치 저장] [💱 환율] [⚡] │  ← 4칸, 시간대별 자동 + 빠른 메뉴
└──────────────────────────────────────────┘
```
- 아침에는 "지금" 자리에 **아침 브리핑**(A2), 저녁에는 **저녁 정리**(A5), 이동 시간대에는 **이동 카드**(B2)
- [오늘][내일] 탭은 없애고 저녁 정리 안에 "내일 미리보기"(A6)

## 5. 단계 제안
| 단계 | 내용 | 비용·의존성 |
|---|---|---|
| 1 | A3 나갈 시각(이동 시간 없을 땐 여유만), A6 탭 정리, C3 지난 일정 접기, D1 긴급 버튼, D2 오늘 주의 한 줄 | 무료, 기기 안 계산 |
| 2 | A1 하루 단계 자동 전환 + A2 아침 브리핑 + A5 저녁 정리, B2 이동 카드 | 무료 |
| 3 | B1 이동 시간 계산, A4 늦어짐 감지, C2 밀어서 다녀옴/건너뛰기 | 경로 API 무료량 안 (guardApi) |
| 4 | C1 시간대별 엄지 버튼, C4·C5, E1·E2 | 무료 |
| 5 | F1 웹 푸시 나갈 시각 알림 | 서버 저장 범위 결정 필요 |

## 6. 정할 것 (하나씩 묻기)
| # | 질문 | 추천 |
|---|---|---|
| Q1 | [오늘][내일] 탭을 없애고 저녁에만 "내일 미리보기"로 바꿀까요? | 바꾸기 |
| Q2 | "남은 N분" 대신 "N시 N분에 나가요"를 크게 보여 줄까요? (둘 다 두면 복잡) | 나갈 시각 크게, 남은 분은 작게 |
| Q3 | 엄지 버튼을 시간대별로 자동으로 바꿀까요, 사용자가 고른 그대로 둘까요? | 숙소로 길찾기 고정 + 나머지 3칸 자동 |
| Q4 | 이동 시간 계산에 경로 API를 쓸까요? (다음 일정마다 1회, 캐시) | 쓰기, 무료량 넘으면 자동 중지 |
| Q5 | 늦어짐 감지 때 다음 일정 시각을 그날만 밀어 보여 줄까요, 실제로 저장할까요? | 보여 주기만 (고치지 않는다 원칙) |
| Q6 | 앱이 닫혀 있어도 웹 푸시로 나갈 시각을 알릴까요? (서버에 보낼 시각만 저장) | 3단계 뒤에 따로 결정 |

### 6.1 결정 (2026-11-04, 사용자)
- Q1 [오늘][내일] 탭 없앰 → 저녁 정리 안의 "내일 미리보기"
- Q2 나갈 시각 크게, 남은 분 작게
- Q3 엄지 버튼 = 숙소로 길찾기 고정 + 시간대별 3칸 (아침 날씨·준비물·예약 / 낮 환율·번역·예약 / 저녁 예약·날씨·필수 항목)
- Q4 이동 시간은 경로 API(앞 일정 장소 → 다음 장소, 기기에 7일 보관), 무료량 안에서만
- Q5 늦어짐 감지(A4)는 넣지 않음
- Q6 웹 푸시는 나중에 따로

## 7. 지키는 규칙
- 좌표·위치를 서버에 보내거나 저장하지 않는다 (경로 계산은 이미 있는 서버 프록시 규칙 그대로, 로그 금지)
- 새 기능은 실험실 `travelMode` 안에서만 (켜고 끄기)
- 문구는 한 줄 = 한 문장, 휴대폰 한 줄 안쪽
- 버튼 색 규칙(docs/11 §7.1): 확인 파랑 · 취소 빨강 · 넘어가기 회색
