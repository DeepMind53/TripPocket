# 06. 로컬 저장 · 백업 · 공유 전략

로컬 모드에서 "데이터는 휴대폰에만 저장"은 장점이자 **가장 큰 리스크(유실)** 다. 이 문서가 그 리스크를 다룬다.
(v0.2: 로그인 시 홈 서버 동기화 추가 → 5절)

## 1. 저장소 선택: IndexedDB
| 후보 | 판단 |
|---|---|
| localStorage | ❌ 5MB 한계, 동기 API, Blob 불가 |
| **IndexedDB (Dexie)** | ✅ 대용량, Blob(첨부) 저장, 트랜잭션, 인덱스 |
| OPFS (Origin Private File System) | △ 첨부 파일 저장소로 향후 고려 |
| SQLite WASM | △ 강력하지만 번들 크기·복잡도 과함 |

## 2. 유실 리스크와 대응
| 리스크 | 상황 | 대응 |
|---|---|---|
| **iOS Safari 7일 규칙** | 홈 화면에 추가하지 않은 사이트는 7일간 사용 안 하면 스크립트 저장 데이터가 삭제될 수 있음 | ① 홈 화면 설치 적극 유도(S-18) — 설치된 웹앱은 이 규칙 예외 ② 백업 리마인더 |
| 저장공간 압박 시 브라우저 정리 | 기기 용량 부족 | `navigator.storage.persist()` 요청 → 결과를 설정 화면에 표시 |
| 사용자가 사이트 데이터/방문기록 삭제 | 브라우저 설정 | 설정 화면에 경고 문구, 정기 백업 |
| 기기 분실/교체 | — | 백업 파일 (사용자의 iCloud/구글드라이브/카톡 나에게 보내기 등) |
| 도메인 변경 | origin이 바뀌면 데이터 접근 불가 | **도메인을 초기에 확정**하고 바꾸지 않는다 ⚠️ |
| 인앱 브라우저 (카톡/인스타 내 브라우저) | 저장소가 분리되거나 휘발됨 | 인앱 브라우저 감지 → "Safari/Chrome으로 열기" 안내 |

## 3. 백업 (Export / Import)
### 3.1 포맷
```jsonc
{
  "format": "travel-planner-backup",
  "schemaVersion": 1,
  "exportedAt": "2026-10-22T10:00:00.000Z",
  "app": { "version": "0.1.0" },
  "scope": "all",               // "all" | "trip"
  "data": {
    "trips": [...], "items": [...], "bookings": [...],
    "savedPlaces": [...], "checklistItems": [...],
    "checklistTemplates": [...], "settings": [...]
  },
  "attachments": "excluded"     // "excluded" | "inline-base64" | "zip"
}
```
- 파일명: `travel-backup-2026-10-22.json` / 여행 단위: `trip-도쿄가을여행-2026-10-22.json`
- 첨부 포함 백업은 ZIP (`fflate`로 클라이언트에서 생성) ⚠️ P1

### 3.2 내보내기 경로
1. **Web Share API (Level 2, 파일 공유)** 지원 시 → OS 공유 시트(카톡, 드라이브, 메일, 파일 앱)
2. 미지원 시 → `<a download>` 파일 다운로드

### 3.3 가져오기 절차
```
파일 선택 → JSON 파싱 → format/schemaVersion 확인 → migrateBackup() → Zod 검증
 → 미리보기(여행 n개, 아이템 n개) → 모드 선택
     ├─ [병합] 같은 id는 updatedAt 최신 쪽 채택, 없는 건 추가
     ├─ [새로 추가] 모든 id 재발급 후 추가 (공유받은 여행 복사본)
     └─ [전체 교체] 현재 데이터 백업 다운로드 권유 → 비우고 삽입
 → 단일 트랜잭션으로 커밋 (실패 시 전체 롤백)
```

### 3.4 백업 리마인더
- `lastBackupAt`이 14일 이상 지났고 데이터 변경이 있었으면 홈에 배너 (닫기 가능, 7일간 숨김).
- 여행 시작 전날에 "여행 전 백업해 두세요" 1회 배너.

## 4. 공유 (서버 없이)
| 방식 | 설명 | 우선 |
|---|---|---|
| **여행 파일 공유** | 여행 1건 JSON → 공유 시트 → 상대가 앱에서 [가져오기] | P0 |
| **링크 공유** | 여행 데이터 → JSON → 압축(`lz-string` 또는 `CompressionStream` deflate) → base64url → `https://도메인/#/import?d=...` | P1 |
| **읽기 전용 보기** | 링크 열면 저장 없이 미리보기, [내 앱에 저장] 버튼 | P1 |
| **텍스트 공유** | 카톡에 붙여넣기 좋은 일정 텍스트 요약 | P1 |
| **인쇄/PDF** | 인쇄 전용 CSS로 일정표 | P1 |
| **.ics** | 일정을 캘린더 앱에 추가 | P1 |

- 링크 길이 한계: URL은 대략 수만 자 이내가 안전 → 압축 후 **약 8KB 초과 시 링크 공유 비활성화하고 파일 공유 안내** ⚠️ (실측 후 확정).
- 데이터는 URL **fragment(#)** 에 담아 서버 로그에 남지 않게 한다.
- 공유 시 "예약번호·연락처·메모 제외" 토글 (기본: 예약번호·연락처 제외 ⚠️).

## 5. 홈 서버 동기화 (v0.2 추가)
- 로그인 사용자는 홈 PC 서버와 자동 동기화 → 기기 분실·교체에도 데이터 보존. 2절의 유실 위험이 크게 줄어든다.
- 그래도 **로컬 JSON 백업 기능은 유지**한다 (서버 장애·탈퇴·서버 종료 대비, 데이터 소유권).
- 로그인 사용자의 공유는 "초대 링크(공동 편집)"가 기본. 파일/링크 공유는 비로그인 사용자용으로 유지.
- 상세 프로토콜·보안: `09-server-auth-security.md` §6~7.
