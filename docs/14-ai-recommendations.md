## 2. 데이터 출처 — 무엇을 쓸 수 있고 무엇을 못 쓰나
| 출처 | 사용 방법 | 최신성 필터 | 판단 |
|---|---|---|---|
| **네이버 검색 API – 블로그** (`/v1/search/blog`) | "신주쿠역 맛집" 등 검색, 최신순 정렬, 결과의 작성일(`postdate`)로 기간 필터 | ✅ 작성일 제공 | **주 출처**. 한국 여행자 후기가 많아 해외 여행지(도쿄·오사카 등)에도 강함 |
| 네이버 검색 API – 카페글 | 같은 방식 | △ 작성일 제공 여부 확인 ⚠️ | 보조 |
| 네이버 검색 API – 지역 | 장소명 → 주소·카테고리 정규화 (국내) | — | 국내 장소 확인용 |
| **Google Places API (New)** | 후보 장소의 평점·리뷰 수·좌표·영업 여부 확인 (10번 문서 프록시 재사용) | 리뷰 작성 시각(최대 5개) | **검증·정렬용**. 언급 수가 아니라 품질 신호 |
| Google 웹 검색 API (Programmable Search JSON API) | 기간 제한(`dateRestrict`) 검색 | ✅ | ⚠️ 신규 사용 제한·종료 예정 공지가 있었음 → **개발 전 사용 가능 여부 확인**, 불가하면 제외 |
| 인스타그램·틱톡·네이버 플레이스 리뷰 화면 | — | — | ❌ 공식 API 없음, 화면 수집(스크래핑)은 약관 위반 → 사용 안 함 |
| Claude 웹 검색 도구 (`web_search`) | AI가 직접 웹 검색 | △ 기간 제어가 약함 | 대안(국내 블로그가 부족한 지역용) ⚠️ K4 |

> **결론**: "가장 많이 나오는 곳" = **네이버 블로그 최근 언급 수**(주) + **Google 평점·리뷰 수**(보정).
> 구글 "검색 결과 노출 횟수"는 공식 API로 얻을 수 없으므로 대신 Google Places의 리뷰 수를 인기 신호로 사용한다.

```
  │

  │    · 좌표 → 가장 가까운 역: 국내=카카오 로컬 '지하철역' 카테고리 검색 / 해외=Google Places Nearby(train/subway station) ⚠️

  │
  │ 4) 수집 — 단계별 기간 확장 (§4)
  │    네이버 블로그: "{기준점} 맛집" / "{기준점} 핫플" / "{기준점} 가볼만한곳" / "{기준점} 놀거리"
  │    최신순으로 페이지를 넘기며 기간 안의 글만 모음 (최대 300건)
  │
  │ 5) AI 추출·정리 (§5) — 글 제목·요약문에서 장소명 추출, 같은 곳 묶기, 광고성 표시, 카테고리 분류
  │
  │ 6) 검증·보강 — 상위 후보를 Google Places Text Search로 확인 → 평점·리뷰 수·좌표·영업 상태
  │    확인 안 되는 후보는 "정보 확인 필요" 표시 또는 제외
  │
  │ 7) 점수 계산·정렬 (§6) → 카테고리별 상위 5개
  ▼
[웹앱] 결과 화면 (S-52) — 근거·기간 표시, 기기에 마지막 결과 저장(오프라인 열람)
```

## 4. 기간 단계 확장 규칙
| 단계 | 기간 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| 1 | 오늘 기준 최근 **1개월** | 카테고리별로 **언급 2회 이상인 장소가 5곳 미만** |
| 2 | 최근 **3개월** | 위와 같음 |
| 3 | 최근 **6개월** | 위와 같음 |
| 4 | 최근 **12개월** (상한) | 그래도 부족하면 있는 만큼만 보여주고 "정보가 적은 지역이에요" 안내 |
- 카테고리마다 따로 판단한다 (맛집은 1개월로 충분, 놀거리는 3개월로 확장 등).
- 확장해도 **최근 언급에 가중치**를 둔다 (§6) → 오래된 인기 장소가 최근 핫플을 덮지 않게.
- 화면에 사용한 기간을 표시: `최근 1개월 기준` / `정보가 적어 최근 3개월로 넓혔어요`.
- 임계값(2회, 5곳)은 설정값으로 두고 실측 후 조정 ⚠️ K5.

## 5. AI 처리 설계 (Claude API)
### 5.1 역할 분담 — AI가 하는 일과 하지 않는 일
| AI가 하는 일 | AI가 하지 않는 일 |
|---|---|
| 블로그 제목·요약문에서 **장소명 추출** | 장소를 새로 지어내기 (입력에 없는 장소 금지) |
| 표기가 다른 같은 장소 묶기 ("이치란 신주쿠점" = "一蘭 新宿") | 평점·영업시간 판단 (Google 데이터로만) |
| 카테고리 분류 (맛집/카페·핫플/놀거리) | 언급 수 계산 (서버 코드가 원문 ID로 직접 셈) |
| 광고·협찬 의심 표시 ("원고료", "제공받아" 등) | 개인정보 처리 (입력에 위치 좌표·사용자 정보 없음) |
| 장소별 **한 줄 요약** (근거 글 내용 기반, 한국어 해요체) | |

### 5.2 호출 방식
- SDK: `@anthropic-ai/sdk` (TypeScript, 서버 `apps/server/src/services/aiRecommend.ts`)
- 모델: **`claude-opus-5-5`** (기본) — 비용 비교 후 경량 모델(`claude-haiku-5-5`) 전환 여부는 K1에서 결정
- 출력: **구조화 출력**(`output_config.format` + Zod 스키마, `messages.parse()`) → 서버에서 한 번 더 Zod 검증
- `output_config.effort: "low"` (추출·분류는 단순 작업, 실측 후 조정)
- 거절 대비: 서버 측 대체 모델 설정(`fallbacks: "default"`, 베타 헤더 `server-side-fallback-2026-07-01`) + `stop_reason` 확인
- 시스템 프롬프트는 고정 문자열 → 프롬프트 캐싱 적용 (요청마다 바뀌는 블로그 목록은 뒤에)
- 입력: 블로그 글마다 `{ id, title, description, postdate }` (원문 본문은 가져오지 않음 — 요약문만)
- 타임아웃 30초, 실패 시 "잠시 후 다시 시도해 주세요" + 캐시된 이전 결과가 있으면 표시

### 5.3 출력 스키마 (Zod 초안)
```ts
const AiPlace = z.object({
  name: z.string(),                         // 대표 이름 (한국어 우선)
  aliases: z.array(z.string()),             // 원문 표기들
  category: z.enum(["food", "cafe_hot", "activity"]),
  sourceIds: z.array(z.string()).min(1),    // 근거가 된 블로그 글 id — 입력에 있는 id만 허용
  adSuspectIds: z.array(z.string()),        // 광고 의심 글 id
  summary: z.string().max(60),              // 한 줄 요약 (해요체)
});
const AiResult = z.object({ places: z.array(AiPlace).max(40) });
```
- 서버 검증: `sourceIds`가 실제 입력 id에 없으면 그 항목 버림 (지어낸 장소 차단).
- 언급 수·최근 언급일은 서버가 `sourceIds`로 직접 계산.

### 5.4 비용 (조사 시점 단가, 재확인 필요)
| 항목 | 추정 |
|---|---|
| 입력 | 블로그 300건 × 약 60토큰 ≈ 18K 토큰 + 지시문 1K |
| 출력 | 약 2K 토큰 |
| `claude-opus-5-5` ($4 / $20 per 1M) | 1회 약 $0.12 |
| `claude-haiku-5-5` ($0.10 / $0.50 per 1M) | 1회 약 $0.003 |
| Google Places 검증 | 상위 후보 15곳 × Text Search(Enterprise) → 1회 $0.5 내외 ⚠️ 가장 큰 비용 |
- 비용 통제: 사용자당 **하루 5회** ⚠️, 같은 기준점·카테고리는 서버 캐시 6시간 공유, Places 검증은 상위 후보만, Google 결과는 약관상 캐시 제한 → 평점은 화면 표시용으로만 사용하고 저장하지 않음.

## 6. 점수 · 정렬
```
최근 가중 언급 점수  M = Σ (글마다) w(경과일)  ,  w = 0.5 ^ (경과일 / 30)   ← 30일마다 절반
광고 보정            광고 의심 글은 w × 0.3
품질 보정            Q = 가중 평점 (10번 문서 §4.2, Google 평점·리뷰 수) — 없으면 중간값
최종 점수            S = 0.6 × 정규화(M) + 0.4 × 정규화(Q)
```
- 같은 점수면 최근 언급일이 가까운 순.
- 기준점에서 너무 먼 곳(설정 반경 초과, 기본 3km)은 제외 — Google 좌표로 판단.
- 정렬 옵션: AI 추천순(기본) / 언급 많은순 / 평점순 / 가까운순.

- **기준 위치 세그먼트 동작**
  - 가까운 역: 위치 권한 요청 → 거부·꺼짐이면 자동으로 "직접 입력"으로 전환 + 안내 "위치가 꺼져 있어요. 역이나 지역 이름을 입력해 주세요"
  - 숙소: 이 여행 숙소 목록(오늘 숙소 기본 선택)
  - 직접 입력: 검색창 + 자동완성(역·동네 이름) + 최근 입력 3개 칩
- **근거 보기**: 하단 시트에 언급 글 목록(제목 · 블로그명 · 작성일 · 외부 링크), 광고 의심 글은 회색 + "광고 의심" 배지
- **상태**: 수집 중 스켈레톤 + 단계 문구("블로그 글을 모으고 있어요 → AI가 정리하고 있어요"), 결과 없음 / 하루 한도 초과 / 오프라인(마지막 결과 보기) / 비로그인(로그인 안내)
- 마지막 결과는 기기에 저장 → 오프라인에서도 다시 볼 수 있음 (Google 평점은 다시 연결될 때 갱신)

## 8. 보안 · 개인정보 · 약관
| 항목 | 규칙 |
|---|---|
| 위치 | 좌표는 반올림 후 서버로 전송 → 역 이름 변환에만 쓰고 즉시 폐기, 로그·DB·AI 입력에 포함하지 않음 |

| API 키 | Anthropic·네이버·카카오·Google 서버 키는 `.env`, 웹앱 번들에 넣지 않음 |
| 출처 표기 | "네이버 블로그", Google 로고, 원문 링크 제공. 블로그 본문 복제·저장 안 함 (제목·요약문·링크만, 캐시 6시간) |
| 개인정보처리방침 | AI 요청에 개인정보가 포함되지 않음을 명시, 외부 API 호출(국외 포함) 고지 |
| 표시 문구 | "AI 요약은 틀릴 수 있어요" 고지, 광고 의심 표시 |

## 10. 테스트
- 기간 확장 로직: 가짜 블로그 데이터(작성일 분포 조정)로 1→3→6→12개월 전환 조건 검증
- AI 출력 검증: 존재하지 않는 `sourceIds` → 버림, 스키마 위반 → 재시도 1회 후 실패 처리
- 고정 입력 세트(도쿄 신주쿠역, 서울 성수역, 부산 서면역)로 **평가 세트** 구성 → 모델·프롬프트 변경 시 추출 정확도 비교
- 외부 API는 개발 중 fixture 사용 (실제 호출은 명시적 플래그)
- 위치 미전송 확인: 서버 로그에 좌표 패턴이 없는지 자동 검사
