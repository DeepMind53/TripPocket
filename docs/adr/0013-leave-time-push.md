# ADR-0013: 나갈 시각 알림 — 앱이 계산한 시각만 서버에

- 상태: 확정
- 날짜: 2026-11-25

## 배경 (Context)
docs/27 F1: 여행 모드는 다음 일정까지 이동 시간을 재서 "10:50에 나가요"를 보여 준다. 앱이 닫혀 있으면 알 수 없다.
이미 있는 웹 푸시(docs/20 G1, "일정 시작 30분 전")는 이동 시간을 모른다.
CLAUDE.md: 사용자 위치(좌표)를 서버에 저장·기록하지 않는다. 나갈 시각은 지금 위치로 계산할 때가 있다.

사용자 결정(2026-11-25): **앱이 계산한 시각만** 서버에 보낸다.

## 결정 (Decision)
1. 웹이 여행 모드에서 나갈 시각을 계산하면 `PUT /api/push/leave`로 **여행 id·일정 id·날짜·"HH:mm"**만 보낸다. 좌표·현재 위치·이동 수단·이동 시간은 보내지 않는다
2. 서버 표 `push_leave` (마이그레이션 24): 사람·일정마다 한 줄, 다시 보내면 덮어씀. 그 날짜가 지나면 지운다. 탈퇴하면 함께 지운다
3. 서버 알림 계산(5분마다)이 그 여행 시간대로 나갈 시각이 되면(10분 안) 한 번 보낸다 — "지금 나가면 11:00 오사카성에 맞춰요". 같은 일정의 "30분 전" 알림은 보내지 않는다(두 번 울리지 않게)
4. 알림 설정은 기존 "일정 알림"(itemSoon)을 따른다 — 끄면 나갈 시각 알림도 안 간다. 새 기능이라 실험실 `leavePush`를 켠 기기만 시각을 보낸다
5. 인가: 로그인 + 그 여행 멤버 + 그 여행의 일정일 때만 받는다

## 검토한 대안
| 대안 | 장점 | 단점 |
|---|---|---|
| 서버가 앞 일정 장소 → 다음 장소 경로를 직접 조회 | 앱이 닫혀 있어도 계산 | 경로 API 호출이 사람·일정마다 늘어남, 지금 위치는 모름 |
| 앱 안 알림만 (서버 없이) | 서버 저장 없음 | 앱이 닫히면 울리지 않음 (지금과 같음) |

## 결과 (Consequences)
- 좋아지는 점: 앱을 닫아도 나갈 시각에 알림. 서버에는 시각 문자열만
- 감수하는 점: 앱을 연 뒤 계산된 시각만 알 수 있다(한 번도 열지 않은 날은 30분 전 알림만). 아이폰은 홈 화면에 설치한 앱에서만 알림
