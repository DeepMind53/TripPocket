# ADR-0003: 홈 PC 동기화 서버 + 로그인 도입

- 상태: 제안 (방향은 사용자 요구, 세부 선택지는 08-open-decisions G 항목에서 확정)
- 날짜: 2026-10-22
- ADR-0001을 **부분 대체**: "서버 없음" → "오프라인 우선 + 선택적 로그인 동기화"

## 배경
사용자가 이 컴퓨터(Windows 11 홈 PC)를 활용해 로그인 후 데이터를 저장·불러오기를 원한다. 보안이 중요하다.
기존 설계(기기 저장만)는 기기 분실·교체, 다기기 사용, 동행자 공동 편집에 약했다.

## 결정
1. 클라이언트는 그대로 **IndexedDB 1차 저장 + 오프라인 우선**. 로그인은 선택 사항이고, 비로그인 로컬 모드도 유지한다.
2. 홈 PC에서 Node.js API 서버 + SQLite 운영. **Cloudflare Tunnel**로 외부에 공개 (인바운드 포트 개방 없음).
3. 웹앱 정적 파일은 Cloudflare Pages에 호스팅 → PC가 꺼져도 앱은 열린다.
4. 인증은 **소셜 로그인(네이버/카카오/구글, OAuth + PKCE)** + 서버 세션 쿠키. 비밀번호는 저장하지 않는다.
5. 동기화는 엔티티 단위 LWW + 서버 rev 기반 push/pull.

## 검토한 대안
| 대안 | 장점 | 단점 |
|---|---|---|
| 서버 없이 유지 | 단순, 운영 부담 0 | 사용자 요구 불충족 |
| Supabase/Firebase | 운영 쉬움, 가용성 높음 | 요구사항(이 컴퓨터 활용)과 다름, 데이터가 외부에 저장 |
| 포트포워딩으로 직접 공개 | 도메인 불필요 | 보안 위험 큼 |
| 서버가 1차 저장소(온라인 전용) | 구현 단순 | 해외 여행 중 오프라인 사용 불가 → 핵심 가치 훼손 |

## 결과
- 좋아지는 점: 기기 간 이동, 공동 편집, 서버 백업으로 유실 위험 감소.
- 감수하는 점: 홈 PC 상시 가동·전기·관리, 보안 책임, 개인정보처리방침 필요(타인 사용 시), 동기화 복잡도.
- 후속 작업: `09-server-auth-security.md` 체크리스트 이행, 모노레포 구조로 변경.
