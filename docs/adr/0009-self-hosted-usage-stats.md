# ADR-0009: 관리자용 사용 통계 — 홈 서버 안에서, 사람 구분 없는 합계만

- 상태: 확정
- 날짜: 2026-11-02

## 배경 (Context)
사용자 요청(2026-11-02): 앞으로 서비스를 다듬기 위해 사용자들이 어떤 기능을 많이 쓰는지 관리자만 볼 수 있게 통계를 낸다.
기능·호출·입력·삭제 등 셀 수 있는 것은 모두 센다.
CLAUDE.md는 별도 ADR 없이 애널리틱스·트래커를 넣지 못하게 한다 → 이 ADR로 범위를 정한다.

사용자 결정(2026-11-02):
- 사용자별로 보지 않는다. **전체 합계만** 저장한다
- 보관 기간 **3년**
- 횟수 외에 사용자·여행 현황, 설정·실험실 켜진 비율, 기기·사용 환경, 서비스 품질도 넣는다

## 결정 (Decision)
1. 외부 분석 SDK·서비스를 쓰지 않는다. 홈 서버 SQLite `usage_stats(date, kind, name, count)`에만 저장한다
2. 저장하는 것은 **날짜·종류·이름·횟수**뿐이다. 사용자 id·입력 내용·장소·검색어·위치·IP는 넣지 않는다
3. 서버에서 세는 것
   - 요청: 경로 패턴(`GET /api/trips/:id` 형태, 값 없음)·실패(4xx·5xx)·한도(429)·응답 시간 구간
   - 동기화: 표별 입력·수정·삭제·복원·충돌
   - AI 추천: 정리한 AI, 0곳, 블로그 근거 수, 캐시 적중
   - 하루 사용자 수: `users.last_active_date`(날짜 하나만 덮어씀)로 그날 처음 쓴 사람만 +1
4. 앱에서 세는 것: 화면·시트 열기(경로의 id는 `:id`), 설정 변경, 실험실 켜기·끄기, 지도 앱 열기, 기기 환경(하루 한 번).
   기기에 횟수만 모았다가 동기화 뒤 `POST /api/stats/events`로 보낸다. 이름은 영문 규칙(`^[a-z][a-zA-Z0-9_.:/-]{0,59}$`)만 받는다
5. 화면에서 바로 계산하는 것(따로 저장 안 함): 가입자·활동 사용자 수, 여행 나라·도시·기간·여행당 항목 수, 함께 쓰는 여행,
   계정 설정 켜진 비율, 로그인 방법, 로그인된 기기의 운영체제·브라우저
6. 보기: `GET /api/admin/stats`는 관리자만(`requireAdmin`). 보내기: 로그인 필수 + Origin 검사 + 분당 10회 + 사람당 하루 5,000회
7. 3년이 지난 통계는 하루 한 번 자동으로 지운다. 개인정보 처리방침에 적는다

## 검토한 대안
| 대안 | 장점 | 단점 |
|---|---|---|
| 외부 분석 서비스(GA 등) | 화면·기능이 많음 | 사용자 데이터가 홈 서버 밖으로 나감(CLAUDE.md 위반), 번들 커짐 |
| 사용자별 기록 | 사람별 흐름 분석 | 개인정보 부담, 탈퇴 처리 필요 — 사용자 결정으로 제외 |
| 서버 로그 분석 | 앱 수정 없음 | 오프라인·앱 안 동작을 못 셈, 로그에 개인정보가 섞일 위험 |

## 결과 (Consequences)
- 좋아지는 점: 많이 쓰는 기능·안 쓰는 기능·느린 API·AI 추천 품질을 관리자가 숫자로 본다
- 감수하는 점: 사람 구분이 없어 "한 사람이 많이 쓴 것"과 "여러 사람이 쓴 것"을 구분하지 못한다(하루 사용자 수 제외).
  앱에서 센 횟수는 로그인한 사용자가 부풀릴 수 있다(하루 상한으로 제한). 응답 시간은 구간으로만 저장해 대략값이다

## 보강 (2026-11-02, 사용자 요청: 설명과 통계 더 많이)
- 관리자 화면: 칸마다 "무엇을 알 수 있는지" 설명, 영문 기능 이름을 한국어로 (`features/me/statLabels.ts`, `ko.json` `stats.names`)
- 추가 통계
  - 재방문: 가입 7일·30일 뒤에도 쓴 사람 비율, 쓴 날 수별 사람 수 (`users.active_days`, 마이그레이션 19)
  - 시간대별 사용 (한국 시각, 로그인한 요청 수)
  - 기능을 쓴 기기 수: 기기마다 기능별 하루 한 번 (`reach.*`) — 횟수와 따로 "몇 명이 쓰는지"
  - 수요: 한도 도달 횟수(`limit.*`), AI 추천을 저장·일정 추가·지도로 연 횟수
  - 장소 검색 결과 없음·백업 검색 비율, 앱 열기(오프라인 포함), 화면 오류 횟수(내용 없음)
- `users.last_active_date`·`active_days`는 계정 행에 숫자만 둔다. 통계 표에는 사람 구분이 없고, 탈퇴하면 계정과 함께 지워진다 (개인정보 처리방침에 적음)
