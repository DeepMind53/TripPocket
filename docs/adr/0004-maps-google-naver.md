# ADR-0004: 구글·네이버 지도 병행 및 길찾기 딥링크

- 상태: 제안
- 날짜: 2026-10-22

## 배경
여행지가 국내/해외 모두이며, 사용자는 구글 지도 또는 네이버 지도를 쓰고 싶어 한다.
숙소·음식점·볼거리의 평점·후기 필터링과 현재 위치에서 길찾기가 필요하다.

## 결정
1. 지도 렌더링은 `MapProvider` 인터페이스로 추상화하고 Google / Naver 구현 2개를 둔다. 기본값: 국내 여행=네이버, 해외=구글, 사용자 변경 가능.
2. **평점·리뷰 검색은 Google Places API (New)** 로 한다. 네이버/카카오는 평점·리뷰 공개 API가 없으므로 링크 연결만 한다. 스크래핑은 하지 않는다.
3. Places 호출은 **홈 서버 프록시**를 거친다 (키 보호, 비용 한도). 로그인 사용자 전용.
4. 길찾기는 **지도 앱/웹 딥링크**로 연결한다 (출발지 생략 = 현재 위치). 앱 내 경로 계산 API는 사용하지 않는다(P2).
5. Google 약관에 따라 Google 장소 데이터는 Google 지도 또는 리스트에만 표시하고, 평점·리뷰는 저장하지 않는다.

## 검토한 대안
| 대안 | 단점 |
|---|---|
| 구글만 사용 | 국내 길찾기·지도 품질 부족 |
| 네이버만 사용 | 해외 품질 부족, 평점·리뷰 API 없음 |
| 리뷰 스크래핑 | 약관 위반·차단·법적 위험 |
| Leaflet + OSM (기존 안) | 평점·리뷰 없음 → 보조 수단으로만 남김(키 없는 오프라인 대체) ⚠️ |

## 결과
- 좋아지는 점: 국내·해외 모두 대응, 길찾기 비용 0.
- 감수하는 점: Google Places 비용(사용량 관리 필요), 두 SDK 유지보수, 약관 준수 부담.
