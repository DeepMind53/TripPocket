# 버그 목록 — 빈도 × 심각도 점수

> 2026-11-17 만듦 (사용자 요청 "버그 분류기"). 버그마다 **발생 빈도**와 **심각도**를 1~10점으로 매기고 곱한다.
> **5 이상**이면 고치고, **5 미만**이면 코드는 건드리지 않고 이 표에만 남긴다. 아무도 요청하지 않은 드문 사례·미래 상황까지 대비해 설계하지 않는다.
> 근거: 최근 CI 실행 150번(103~252번) 기록 + 로컬 재현. GitHub 이슈 대신 이 문서에 기록한다 (사용자 결정).

## 점수 기준

- 빈도: 10 = 매번 / 7 = 자주(10번 중 몇 번) / 4 = 가끔(수십 번에 한 번) / 2 = 드묾(150번 중 1~2번) / 1 = 한 번 본 적 있음
- 심각도: 10 = 데이터 손실·보안 / 7 = 핵심 기능 안 됨 / 4 = 기능은 되지만 화면이 깨지거나 검사가 늘 빨감(진짜 문제를 가림) / 2 = 시험만 가끔 실패(앱 영향 없음) / 1 = 겉모양
