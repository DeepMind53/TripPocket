# 28. 숙소 최저가 비교 — 상세 설계

- 상태: **1~6단계 구현 완료** (2026-11-09, 결과 §12, ADR-0010) — 설정 없이 늘 켜짐, 휴대폰 확인 피드백 대기
- 날짜: 2026-11-09 (초안) → 같은 날 A+B+D+E 혼합 → 같은 날 링크 확인 + 가격 기록 추가
- 요청: 숙소 이름·체크인·체크아웃을 넣고 검색하면 국내외 숙소 예약 앱 3곳 이상(아고다·트립닷컴·여기어때·NOL 등)의
  가격을 한 번에 비교한다. 참고: 아고다스캐너(https://agodascanner.com).
  **무한 검색 요청이 생기지 않도록 방어 코드와 오류 시 검색 중단은 필수**
- 확정된 것 (사용자 결정 2026-11-09)
  - Q1 방식 = A+B+D+E 혼합, 아고다스캐너처럼
  - **가격은 사용자가 링크를 눌러 각 앱에서 확인한다** (아고다 경로 23곳 이상, 경로 수 제한 없음)
  - **본 가격을 사용자가 적어 기록하고, 검색한 날짜와 함께 서버에 30일만 보관해 다른 사람도 목록으로 본다** (§7)
  - 나머지 결정 (Q2~Q10)은 §13 표. 요약: A 링크 6개 앱, 아고다스캐너 버튼 없음, **B 구글 호텔은 링크·기록 다음 단계,
    D 앱 직접 조회는 하지 않음**, 넉넉한 한도, 입력 편의·기록 도움 아이디어, 무료량 넘으면 자동 중지 + 구글 호텔 창 열기,
    기록은 로그인한 모두에게 공개(작성자 비공개), 본 시각은 날짜만

## 1. 목표와 범위

| 한다 | 하지 않는다 |
|---|---|
| 숙소 이름·날짜로 **각 앱 검색 링크** (A) + **아고다 경로별 링크** (E) — 눌러서 가격 확인 | 지역 전체 숙소 목록 검색 (숙소 찾기는 지도·AI 추천 몫) |
| 사용자가 본 가격을 **적어서 기록**, 30일 동안 모두가 목록으로 봄 (§7) | 예약·결제 대행, 내 지출 기록(가계부) — 가격 기록은 "본 가격"이지 쓴 돈이 아님 |
| 구글 호텔(B)로 참고 가격 표시 (링크·기록 다음 단계) — 저장하지 않음 | 자동으로 가져온 가격 저장·공유 (구글 데이터 저장 금지) |
| 버튼을 누를 때만 요청, 한도·차단기로 자동 중지 | **D 예약 앱 직접 조회** (Q4 결정으로 제외), 로봇 확인 풀기·우회, 프록시, 브라우저 위장, 정기 자동 조회 |

## 2. 아고다스캐너 분석 (참고 모델, 2026-11-09 페이지 코드 확인)
- **입력:** 아고다 숙소 링크 하나. 폼은 `GET /result?url=<아고다 링크>` → 주소로 바로 열 수 있다
- **실제 동작:** 결과 화면 스크립트에 **가격을 받아 오는 요청이 없다** (`fetch` 0개, 썸네일 이미지 요청만).
  아고다 링크의 **접속 경로 값(CID)** 을 미리 정해 둔 값으로 바꾼 **링크 23개**를 만들어 보여 줄 뿐이다
  - 검색 경유 7개 (구글 지도 3·구글 검색 3·네이버 검색 1)
  - 카드사 13개 (국민·우리·BC·신한·토스·하나·마스터·비자 등, 일부는 카드사 전용 페이지 링크)
  - 항공사 3개 (대한항공·아시아나·에어서울 적립)
  - 그 밖에 카드·결제 프로모션 페이지 링크 묶음
- 가격은 사용자가 링크를 하나씩 눌러 **아고다 화면에서** 본다. 그래서 23개여도 서버 요청이 없다
- 아고다는 들어온 경로·결제 수단·회원 여부에 따라 값을 다르게 보여 주는 동적 가격이라 경로마다 가격이 다를 수 있다
- **수익:** 프로모션 링크에 제휴 태그(`tag=`)가 붙어 있고 광고·분석 스크립트가 있다. 우리는 **제휴 태그·추적을 넣지 않는다**
- **아쉬운 점 → 우리가 더하는 것:** 눌러 본 가격이 어디에도 남지 않는다. 우리는 **본 가격을 적어 두고 다른 사람과 나눈다** (§7)
- **카드 할인 주의:** 카드사 경로 가격은 그 카드로 결제해야 적용되는 경우가 많고, 원화 결제는 이중환전 수수료(3~8%)가
  붙을 수 있다. 결제 팁 안내 줄은 넣지 않기로 함 (Q7) — 경로 묶음 이름 "카드사"로만 구분

## 3. 전체 구조

```
[웹] 숙소 최저가 시트
  ├ 입력: 숙소 이름·체크인·체크아웃·인원 (+ 아고다 링크 붙여넣기)
  ├ [검색] 1번 누름 ──▶ ① 링크 만들기 (웹, 요청 0, 오프라인 가능)
  │                       A 앱별 검색 링크 · E 아고다 경로별 링크 23곳+
  │                  ──▶ ② GET /api/lodging/reports  (같은 숙소의 30일 가격 기록 목록, 요청 1)
  │                  ──▶ ③ (아고다 링크가 없을 때만) 아고다 숙소 자동 찾기 (서버 → 아고다 1번)
  │                  ──▶ ④ GET /api/lodging/prices  구글 호텔 참고 가격 (저장 안 함, ③과 함께)
  ├ 사용자가 링크를 눌러 각 앱에서 가격 확인 → 돌아와서 [가격 적기]
  └ [저장] 1번 누름 ──▶ POST /api/lodging/reports  (서버 SQLite, 30일 뒤 자동 삭제)
```

- ①은 서버 없이 바로 보인다. ②③④는 같은 [검색] 버튼에서 한 번씩만 (폴링·자동 재요청 없음)
- 한 부분이 실패해도 나머지는 보인다 (링크는 항상 보임)

## 4. 링크 (가격 확인 방법)

### 4.1 A — 앱별 바로 검색 링크 (웹, 요청 0)
- `domain/lodgingLinks.ts` 순수 함수: (숙소 이름, 체크인, 체크아웃, 인원) → 앱별 검색 주소
- 대상 (Q2 확정): 여기어때 · NOL · 아고다(기본 검색) · 트립닷컴 · 부킹닷컴 · 구글 호텔
- 주소 모양은 구현 때 앱마다 실제로 열어 확인. 날짜가 안 들어가는 앱은 "날짜는 앱에서 다시 골라요" 표시
- 휴대폰에 앱이 깔려 있으면 앱으로 열릴 수 있다 (유니버설 링크)
- 테스트: 주소 만들기 단위 테스트 (특수 문자·한글 이름·1박/여러 박)

### 4.2 E — 아고다 경로별 링크 (아고다스캐너 방식, 요청 0)
- **흐름:** ① 아고다 숙소 주소 얻기 → ② 웹이 CID만 바꾼 경로별 링크를 전부 만든다 → 사용자가 눌러 확인.
  ②는 순수 함수(`domain/agodaRoutes.ts`)라 서버 요청 0, 오프라인 가능
- **경로 수: 제한 없음.** 23개 이상 (검색 경유·카드사·항공사 + 카드 프로모션 페이지).
  경로 목록(`{ id, label, group, cid | url, note }`)은 공개 자료로 모아 사용자 확인 후 웹 데이터 파일에 넣는다. 제휴 태그는 넣지 않는다
- **① 아고다 숙소 주소 얻기** (위에서부터 먼저 되는 것):
  1. **아고다 링크 붙여넣기** — 아고다 앱·웹에서 공유한 링크. 요청 0, 가장 정확
  2. **예약에 저장된 아고다 링크** 재사용 — 요청 0
  3. **자동 찾기** — 서버가 아고다 숙소 검색(자동완성) **1번**으로 숙소 id를 찾아 날짜를 넣은 주소를 만든다.
     30일 캐시, 아고다에 보내는 것은 숙소 이름뿐, 하루 100번 상한, 막히면 멈춤 (§9). 사전 점검(§12) 필요
  4. 자동 찾기가 안 되면 아고다 링크 붙여넣기를 안내한다 (이름만으로 여는 아고다 검색 주소는 첫 화면으로 돌아감, §12.1)
- **경로 링크 주소 (§12.1 확인):** `https://www.agoda.com/partners/partnersearch.aspx?hid=<숙소 id>&cid=<경로>&checkin=YYYY-MM-DD&checkout=YYYY-MM-DD&NumberofAdults=<인원>&Rooms=<객실>`.
  붙여 넣은 아고다 숙소 링크는 그 주소의 `cid`만 바꾼다 (아고다스캐너와 같음)
- **앱으로 열림:** 아고다 앱이 깔린 휴대폰에서는 링크가 앱으로 열린다 (경로는 적용됨, §12.1). 막지 않고,
  웹으로 보고 싶을 때를 위해 줄마다 [링크 복사]를 둔다
- **날짜·인원:** 주소의 `checkIn`·`los`(박 수)·`adults`·`rooms`를 입력값으로 맞춘다
- **점검할 것:** 아고다가 처음 들어온 경로를 쿠키로 기억해 두 번째 링크부터 경로가 안 바뀌는지.
  그렇다면 "링크마다 새 시크릿 창" 같은 안내를 붙인다

### 4.3 B — 구글 호텔 참고 가격 (링크·기록 다음 단계, Q4 확정)
- 링크 확인 + 가격 기록이 기본이다. B는 "눌러 보기 전에 대략 얼마인지" 보여 주는 **참고용**이고, **저장·공유하지 않는다**
- **SerpApi `google_hotels`:** 검색 1번에 최대 2번 호출 (`q`, 날짜, `adults`, `currency=KRW`, `gl=kr`, `hl=ko` →
  `property_token` → 예약처별 `prices[]`). 월 250회 무료, 결제 수단 미연결이면 넘을 때 막힐 뿐 → `group: 'free'`.
  키는 서버 `.env` `SERPAPI_KEY` (사용자가 무료 가입 후 넣음)
- **무료량을 다 쓰면 (Q8 확정):** 95%에서 그 달 B 자동 중지 (과금 없음). 참고 가격 자리에
  "이번 달 참고 가격을 다 썼어요" + **[구글 호텔에서 보기]** 버튼 → 숙소 이름·날짜를 넣은 구글 호텔 검색 창을 연다 (A 링크와 같은 주소, 요청 0)
- 자동 가격은 기록 입력칸에 **미리 채우지 않는다** (구글 데이터를 기록으로 옮기는 셈이 되므로). 기록은 사람이 본 값만
- **D 예약 앱 직접 조회는 하지 않는다** (Q4 확정: 약관·IP 차단 위험). 여기어때·NOL·트립닷컴은 A 링크 + 기록으로

## 5. 숙소 확인 (같은 숙소 찾기 — 기록을 묶는 기준)
- 앱마다 숙소 이름이 다르게 적혀 있다 (영문·한글·지점명). 기록 목록이 같은 숙소끼리 모여야 한다
- **숙소 키(`hotelKey`):**
  - 아고다 숙소 id를 알면 `agoda:<id>` (붙여넣기·예약 링크·자동 찾기)
  - 모르면 `name:<정규화 이름>|<도시>` — 소문자, 공백·기호 제거, "호텔/hotel/the" 같은 흔한 말 빼기
  - 같은 숙소가 두 키로 나뉘면 서버의 대응표(정규화 이름 → 아고다 id, 30일)로 합쳐서 보여 준다
- 예약 탭 숙소에서 열면 이름·주소(도시)·날짜·인원이 채워진다. 숙소 예약에 아고다 링크가 있으면 그것을 먼저 쓴다
- 애매하면 (자동 찾기 후보가 여러 개) 후보 3개를 보여 주고 "이 숙소가 맞나요?" — 고르면 그때 링크·기록 목록을 보여 줌

| 기록 없음 | "아직 기록이 없어요\n본 가격을 적어 주세요" |
| 오래된 기록 | 7일 넘은 줄은 흐리게 + "가격이 바뀌었을 수 있어요" |
| 다른 날짜 기록 | 접어서 "다른 날짜" 아래 (날짜·박 수·인원 표시) |
| 이상한 값 | 같은 숙소·날짜 기록의 중앙값보다 5배↑ 또는 1/5↓면 "확인 필요" 표시, 최저가에서 뺌 |
| 오프라인 | 링크만 보임, 기록 영역은 "연결되면 기록이 보여요", [적기] 잠금 |
| 오늘 적기 한도 | "오늘은 더 적을 수 없어요" |
| 구글 호텔 무료량 끝 | "이번 달 참고 가격을 다 썼어요" + [구글 호텔에서 보기] |
| 아래 안내 | "다른 사람이 본 가격이에요\n지금은 다를 수 있어요" |

## 7. 가격 기록 (사용자가 적음 · 30일 · 모두 함께 봄)

### 7.1 저장하는 것 (필요한 것만)
서버 SQLite 새 표 `lodging_price_reports` (마이그레이션 추가)

| 칸 | 내용 | 다른 사람에게 보임 |
|---|---|---|
| `id` | 무작위 id | ○ (삭제용) |
| `hotel_key` | §5 숙소 키 | ○ |
| `hotel_name` | 표시용 이름 (80자) | ○ |
| `city` | 도시 (40자, 선택) | ○ |
| `check_in`, `nights`, `adults`, `rooms` | 검색 조건 (`YYYY-MM-DD`, 1~30박, 1~8명, 1~4실) | ○ |
| `site`, `route` | 앱(`agoda`·`tripcom`·`yeogi`·`nol`·`booking`·`google`·`other`) + 아고다 경로 id (선택) | ○ |
| `price`, `price_type`, `currency` | 정수 금액, `nightly`·`total`, 통화 3자리 | ○ |
| `tax` | `incl`·`excl`·`unknown` | ○ |
| `tags` | 선택 칩 (`member`·`app_only`·`non_refundable`·`breakfast`) | ○ |
| `seen_at` | **검색해서 본 시각** (서버 시각, 정렬용) | **날짜만** (MM.DD, Q10 확정) |
| `user_id` | 적은 사람 — 내 기록 삭제·하루 한도에만 사용 | **✗ 절대 안 보임** (응답에는 `mine: true/false`만) |
| `expires_at` | `seen_at + 30일` | ✗ |

- **저장하지 않는 것:** 이름·닉네임·사진, 여행 id·여행 이름, 좌표, 예약 번호·예약 링크, 자유 메모, 자동으로 가져온 가격(B)
- **30일 삭제:** 목록 조회에서 `expires_at`이 지난 줄은 빼고, 서버가 켜질 때 + 6시간마다 지운다
- **탈퇴:** 그 사람 기록은 즉시 삭제 (`user_id` 외래 키 `ON DELETE CASCADE`). 후기(이름 가리고 남김)와 다르게 지운다
- 백업 JSON에는 넣지 않는다 (서버의 공용 정보, 30일이면 사라짐). Dexie 표도 만들지 않는다 (온라인 전용)
- "가계부 제외" 규칙과의 관계: 내가 쓴 돈이 아니라 **본 가격 제보**이고, 예약·여행과 이어 붙이지 않는다. ADR-0010에 기록

### 7.2 API
| API | 내용 |
|---|---|
| `GET /api/lodging/reports?hotelKey=&checkIn=&nights=&adults=` | 그 숙소의 30일 안 기록, 최대 100줄. 같은 날짜·인원 먼저, 그 안에서 1박 원화 환산 가격 낮은 순. 각 줄 `mine` 포함, `user_id` 없음 |
| `POST /api/lodging/reports` | 기록 1줄 저장 → 저장된 줄 돌려줌 |
| `DELETE /api/lodging/reports/:id` | 내 기록만 (남의 것 403, 관리자는 모두) |
| `GET /api/admin/lodging/reports` | 관리자: 개수·최근 기록 보기·지우기 (잘못된 기록 정리) |

- 모두 `requireUser`. 로그인한 사람이면 누구나 같은 숙소 기록을 본다 (Q9 확정: 로그인한 모두, 작성자 비공개)
- 1박/총액 섞여 있어도 비교되게 화면에서 1박 가격으로 맞춘다 (`총액 ÷ 박 수`, "계산" 표시). 다른 통화는 기존 환율로 환산 + "환산" 표시

### 7.3 기록 검사·남용 막기
| 막기 | 내용 |
|---|---|
| 입력 검사 (zod, 공용 스키마) | 금액 정수 1 이상, 1박 원화 환산 5,000 ~ 20,000,000원, 날짜 형식, 체크인은 오늘−1일 ~ 1년 이내, 통화는 환율 목록에 있는 것 |
| 같은 것 다시 적기 | 같은 사람·숙소·날짜·인원·앱·경로를 1시간 안에 다시 적으면 새 줄 대신 **덮어씀** |
| 사람별 한도 | 적기 **분당 10회 · 하루 60회** (Q6 확정: 넉넉하게), 목록 보기 분당 10회 |
| 숙소별 상한 | 한 숙소 키에 30일 기록 최대 300줄 — 넘으면 가장 오래된 줄부터 지움 |
| 이상한 값 | 저장은 하되 "확인 필요" 표시·최저가 제외 (§6.4). 관리자가 지울 수 있음 |
| 표 전체 상한 | 5만 줄 넘으면 오래된 것부터 정리 (디스크 보호) |

## 8. 무한 요청 방지 · 오류 시 중단 (필수)

### 8.1 화면 (웹)
| 방어 | 내용 |
|---|---|
| 누를 때만 | 입력·시트 열기·화면 이동으로 자동 요청 없음. `useEffect` 안에서 검색·목록 요청 금지 (코드 리뷰 체크) |
| 잠금 | 검색 중·저장 중 버튼 잠금 + 진행 중 요청이 있으면 새 요청을 만들지 않음 (종류마다 1개) |
| 재사용 | 같은 조건 목록은 5분, 참고 가격(B)은 6시간 기기 캐시 → 다시 열어도 요청 0 |
| 재시도 없음 | 실패해도 자동 재시도 0번. 사용자가 다시 누르는 것만 |
| 연타 막기 | 검색 1분에 5번 넘게 누르면 1분 잠금 |
| 시간 제한 | 목록·저장 10초, 참고 가격 25초 + 시트를 닫으면 `AbortController`로 취소 |
| 서버 거절 | 429·503 응답은 `retryAfter` 동안 버튼 잠금 |
| 돌아오면 묻기 | 링크 1번당 1번만 띄움, 요청 없음 |

### 8.2 서버 — 요청 입구
| 방어 | 내용 |
|---|---|
| 로그인 | 모든 API `requireUser` (인가 누락 테스트 포함). 내 기록 삭제는 본인 확인 |
| 입력 검사 | 이름 1~80자, 체크아웃 > 체크인, 최대 30박, 인원 1~8 |
| 사람별 한도 | 검색(자동 찾기·참고 가격) **분당 5회 · 하루 60회** (Q6 확정), 기록은 §7.3 |
| 전체 동시 실행 | 외부 요청이 있는 검색은 서버 전체에서 **동시에 2개까지**. 넘으면 503 "잠시 뒤 다시" |
| 캐시 | 자동 찾기 결과 30일, 참고 가격 6시간 서버 메모리 (사용자 구분 없이 공유). 같은 조건 동시 요청은 하나로 합침 |
| 마감 | 참고 가격 검색 1번 전체 마감 **20초**. 넘으면 끝난 소스만 돌려주고 나머지 취소 |
| 전체 끄기 | `.env` `LODGING_PRICE_SOURCES=agoda_lookup,serpapi` 로 소스 켜고 끄기 + 관리자 화면 끄기 버튼. 기록 기능은 실험실로 끄기 |

### 8.3 서버 — 외부 요청 예산
| 소스 | 검색 1번당 외부 요청 | 상한 (`apiUsage`) | 비고 |
|---|---|---|---|
| A·E 링크 | **0** | — | 경로 수 제한 없음 |
| 가격 기록 | **0** (우리 서버만) | — | §7.3 한도 |
| `agoda_lookup` (숙소 자동 찾기) | 최대 1 (링크 있으면 0) | 하루 100 | 30일 캐시 |
| B `serpapi_hotels` | 최대 2 | 월 250 (95%에서 자동 중지 → 구글 호텔 창 열기 버튼) | 서버 전체 시간당 40으로 따로 막음 (SerpApi 시간당 50 아래) |
| **합계** | **최대 3** | | 반복문으로 페이지를 넘기지 않음. 요청 수는 코드 상수로 상한 |

- 모든 외부 요청은 `guardApi` → 요청 → `trackApi`. 새 id를 `APIS`에 등록 (`group: 'free'`, 스스로 정한 `freeDaily`)
- 요청 하나하나에 시간 제한 **8초**, 응답 크기 상한 **2MB**, 리다이렉트 최대 2번, 다른 도메인으로 가는 리다이렉트 거부

### 8.4 서버 — 소스별 차단기 (오류 시 중단)
| 신호 | 동작 |
|---|---|
| 연속 실패 3번 (시간 초과·5xx·모양 다름) | 그 소스 **30분 중지** |
| **차단 신호** — 403·429, 로봇 확인 페이지, 알 수 없는 리다이렉트 | 그 소스 **24시간 중지** + 관리자 화면 경고. 진행 중인 그 소스 요청도 즉시 중단 |
| 일주일에 차단 신호 3번 | 그 소스 **자동 끄기** — 관리자가 다시 켤 때까지 |
| 응답 모양이 바뀜 (스키마 실패 5번 연속) | 그 소스 끄기 + "사이트가 바뀐 것 같아요" 경고 |
| SerpApi 무료량 95% | `guardApi`가 막음 → 그 달 B 중지 (과금 없음) |

- 차단기 상태는 서버 메모리 + `api_usage` 표에 기록해 재시작해도 이어진다
- 중지된 소스는 호출하지 않고 바로 "잠시 쉬는 중"으로 응답 (요청 0). 자동 찾기가 멈추면 "아고다 링크를 붙여 넣어 주세요"

### 8.5 테스트 (CI에서 실제 외부 호출 없음)
- 순수 함수: 링크 만들기(A·E), 숙소 키 정규화, 1박 환산·이상값 판정, 목록 정렬
- 서버 기록: 로그인 필요, 입력 검사, 1시간 덮어쓰기, 분당·하루 한도, 숙소별 300줄, **응답에 `user_id` 없음**, 남의 기록 삭제 403,
  30일 지난 줄 안 보임·정리 작업, 탈퇴 시 삭제, 마이그레이션 테스트
- 서버 외부 요청: 사람별 한도, 동시 2개, 캐시·합치기, 마감, 예산 상한, 차단기 3단계, fixture로 자동 찾기·구글 호텔 응답 읽기·차단 판정,
  무료량 95%에서 B 중지 + 응답에 "구글 호텔 창 열기" 상태
- 웹: 버튼 1번 = 요청 1번, 잠금 중 다시 눌러도 요청 없음, 실패 후 자동 요청 없음, 시트 닫으면 취소,
  가격 적기 → 목록에 붙음(다시 불러오기 없음), 돌아오면 묻기 1번만 (Vitest + Playwright)
- 실제 호출 확인은 임시 `apps/server/test/zz-live.test.ts`에서만, 끝나면 지운다

## 10. 개인정보·약관·문서
- **다른 사람에게 보이는 것:** 숙소 이름·도시, 숙박 날짜·박 수·인원, 앱·경로, 가격, 본 날짜. **누가 적었는지는 안 보임**
- **주의:** 앱 사용자가 적은 편이라 "누가 이 숙소에 이 날짜로 가는지" 짐작될 수 있다 →
  적기 화면에 "다른 사람도 30일 동안 볼 수 있어요" 안내, 본 시각은 날짜만 보이기, 내 기록은 언제든 삭제
- **외부로 보내는 것:** 아고다 자동 찾기에 숙소 이름(+도시)만. B(SerpApi)에 숙소 이름·도시·날짜·인원·통화만.
  사용자 정보·좌표·여행 이름·가격 기록은 외부로 보내지 않는다
- 기록(로그)에는 사용자 id와 숙소 이름을 함께 남기지 않음 (횟수만)
- **새 ADR-0010 "숙소 가격 확인·기록"**: 아고다 경로 링크, 아고다 자동 찾기(외부 전송), 사용자 가격 기록의 30일 공유 보관,
  가계부 제외 규칙과의 구분, B(SerpApi) 외부 전송, D 직접 조회는 하지 않음
- 개인정보 처리방침에 "숙소 가격 기록 (30일 보관, 다른 사용자에게 공개, 작성자 비공개)" 추가

## 14. 단계 (단계마다 사용자 확인 후 다음으로)

2. **링크** ✅ (2026-11-09): 실험실 `lodgingPrice`, 입력·아고다 링크 붙여넣기·최근 검색, A·E 링크 (서버 없음). 예약 카드·바로가기는 `/lodging-price` 화면, 숙소 예약 시트에서는 쓰던 칸이 사라지지 않게 시트로. 요청 방어(잠금·연타·취소)는 첫 요청이 생기는 3단계에서

4. **아고다 자동 찾기** ✅ (2026-11-09, 실제 1회 확인: 706347): 서버 1번 요청 + 캐시·한도·차단기
5. **B 구글 호텔 참고 가격** ✅ (2026-11-09, 실제 3회 확인 §12.3): `GET /api/lodging/prices` + 6시간 캐시·한도·시간당 40·차단기,
   [검색] 때 아고다 찾기와 함께 1번, 무료량이 끝나면 안내 + [구글 호텔에서 보기]. 개인정보 처리방침에 외부 전송 추가
6. **관리자 화면** ✅ (2026-11-09): 마이 → 관리자 → "숙소 최저가 관리"(`/admin/lodging`). 소스(아고다 자동 찾기·SerpApi)마다
