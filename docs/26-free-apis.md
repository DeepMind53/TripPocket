# 26. 무료 API 더 쓰기 — 설계 제안

- 상태: **1~3단계 적용 (2026-11-03)** — 1단계 A3·A4·C1 정식/설정, 2·3단계 A1(관리자 입국 정보 점검)·A2(외교부 안전공지, 실험실)·B1(국내 축제·행사, 실험실)·B5(국내 오늘 미세먼지)·B2(항공편 지연, 실험실). 공공데이터포털 4종(EntranceVisaService2·CountrySafetyService7·KorService2·ArpltnInforInqireSvc)은 **활용신청 승인 전에는 비어 있음**, AirLabs는 `AIRLABS_KEY`가 있어야 동작. 보류: B3·B4·B6·C2·C3
- 날짜: 2026-11-03
- 요청: 여행 정보·일정·조사에 쓸 수 있는 무료 API를 더 찾고, 앱 어디에 어떻게 붙일지 먼저 설계

## 0. 지키는 원칙 (CLAUDE.md)
| 원칙 | 이 문서에서 |
|---|---|
| 무료 먼저 | 아래 모두 무료(키 발급만). 무료 한도를 넘으면 **멈추고 기존 화면만** (과금 없음) |
| 사용자 데이터는 홈 서버 밖으로 보내지 않음 | 외부로 가는 것은 **여행지 이름·도시 좌표·공항 코드·나라 코드**뿐. 내 위치·일정 내용·사용자 정보는 보내지 않음 |
| 서버의 외부 호출은 `guardApi`·`trackApi` | 키가 필요한 API는 서버를 거치고 `APIS`에 무료 한도와 함께 등록 (관리자 사용량·자동 중지) |
| 새 기능은 실험실 먼저 | 화면에 붙이는 것은 모두 `labsStore` 실험으로 시작 |
| 오프라인 우선 | 받은 값은 기기(IndexedDB)·서버에 저장해 두고, 인터넷이 없으면 마지막 값 + 확인 시각 |
| 번들 작게 | 새 라이브러리 없음 (fetch + zod/mini) |

## 2. 어디에 어떻게 (화면별)

### 2.1 여행 정보
1. **입국 필수 항목 자동 점검 (A1)** — 서버가 주 1회 나라별 무비자 기간을 받아 서버 DB에 저장하고,
   앱에 담긴 값(`essentials.ts`)과 다르면 관리자 화면·월간 갱신 요청문에 "외교부 값과 다름: 태국 90일 → 60일" 표시.
   사용자 화면은 바꾸지 않는다 (공식 값 확인 뒤 사람이 고침) — 틀린 정보가 자동으로 나가지 않게.
2. **미세먼지·자외선 (A3, 국내는 B5)** — 지금 날씨 요청에 대기질 요청 하나를 더해 같은 칸에.
   나쁨 이상·자외선 8 이상인 날만 날씨 그림 옆에 작은 표시, 누르면 이유 팝업 (지금 날씨 주의 팝업과 같은 모양).
3. **안전 공지 (A2)** — 여행지 특보 카드(docs/24) 아래 "외교부 안전 공지" 최신 1건 + 원문 링크.

### 2.2 일정
4. **여행 기간 축제·행사 (B1, 국내)** — 여행 날짜와 지역으로 TourAPI 행사 정보를 받아 "이 기간 열리는 행사" 목록 →
   [가고 싶은 곳에 넣기]. AI 추천에도 근거(원문 id) 데이터로 넣는다 (docs/14 §5 근거 원칙 그대로).
5. **항공편 보조·지연 (B2)** — 지금 항공편 조회(AviationStack → 인천·한국공항공사) 뒤에 AirLabs를 한 단계 더.
   출발 당일 지연이 있으면 항공 카드에 "지연 30분" (월 1,000회라 출발 당일 사용자 요청 때만).
6. **출국장 혼잡 (B3)** — 공항공사와 문구 협의가 끝나면 공항 정보 카드에.

### 2.3 조사·도구
7. **여행지 소개 (A4)** — 여행 만들 때 고른 도시의 위키백과 요약 한두 문장 + "위키백과" 링크.
   서버가 받아 30일 저장 (같은 도시는 한 번만). 장소 상세에도 같은 방식.
8. **환율 보조 2번 (C1)** — 수출입은행이 실패하면 지금 currency-api, 그것도 실패하면 Frankfurter.
9. **나라 기본정보 (C2)** — 빌드 스크립트로 한 번 받아 JSON으로 넣고 월간 갱신 때 다시 생성.

## 3. 구조
```
앱(브라우저) ── 키 없는 API(A3·A4는 서버 경유 권장) ──▶ 외부
     │
     └─ /api/info/* ──▶ 홈 서버 ── guardApi·trackApi ──▶ 공공데이터·AirLabs·TourAPI·Wikipedia
                          └ 서버 캐시(SQLite): 나라·도시·날짜 단위로 저장, 사용자와 묶지 않음
```
- 새 서버 라우트: `routes/info.ts` (로그인 필요, `requireUser`) — `GET /api/info/entry/:cc`, `/air?lat&lng`(도시 좌표 둘째 자리 반올림),
  `/summary?title`, `/events?area&from&to`
- `APIS`에 추가: `mofa_entry`, `mofa_safety`, `tourapi`, `airlabs`(월 1,000), `wikipedia`, `airkorea`, `frankfurter`(브라우저)
- 캐시 기간: 입국요건 7일 · 안전공지 6시간 · 대기질 1시간 · 위키 30일 · 행사 1일 · 항공 지연 10분
- 법적 고지 `DATA_SOURCES`에 출처 추가 (CAMS·위키백과 CC BY-SA·공공누리)

## 4. 단계 (각 단계 끝에 사용자 확인)
1. **1단계 (키 없음·바로 가능)**: A3 미세먼지·자외선, A4 여행지 소개, C1 환율 보조 — 실험실로
2. **2단계 (공공데이터 키 활용신청)**: A1 입국요건 자동 점검(관리자), B1 축제·행사, B5 국내 미세먼지
3. **3단계**: B2 AirLabs 보조·지연, A2 안전 공지
4. **보류**: B3 혼잡도(협의), B4 버스 도착(정류장 연결 설계 필요), B6, C2, C3

## 6. 확인 방법
- 각 API: 서버 단위 시험(가짜 응답) + 인가 누락 시험(로그인 없이 401)
- 무료 한도 95%에서 자동 중지되는지 (apiUsage 시험)
- 비행기 모드: 받은 값이 마지막 값 + 확인 시각으로 보이는지 (offline E2E)
- 외부로 나가는 요청에 내 위치·사용자 정보가 없는지 (요청 주소 검사 시험)
