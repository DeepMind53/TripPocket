## 3. 상세 설계

공통: 모든 문구는 `i18n/ko.json`, 360px에서 먼저 확인, 터치 영역 44px 이상, 색은 디자인 토큰만.

### A1. ⚡ 플로팅 버튼이 내용을 가리지 않게

**지금**: `FloatingQuickButton` — 오른쪽, 화면 가운데보다 조금 아래, 크기 56px, 끌어서 옮김(기기에 저장).

**바꿀 것**
1. **스크롤하는 동안 작아짐**: 아래로 스크롤하면 56 → 40px + 반투명(70%), 멈추고 0.8초 뒤 원래대로. 위로 스크롤하면 바로 원래대로.
2. **목록 끝 여백**: 화면 맨 아래 내용이 버튼에 가리지 않게 목록 아래 여백을 버튼 높이만큼 (`useBottomInset`에 버튼 몫 추가).
3. **기본 위치 조정**: 처음 위치를 오른쪽 가운데 아래 → **하단 탭 바로 위 오른쪽**(엄지 영역, 목록 오른쪽 끝의 종류 표시와 덜 겹침). 이미 옮긴 사람은 그대로.
4. 카드 오른쪽 끝 정보(종류 표시)는 버튼 아래에 있어도 **카드를 누르면 상세에 똑같이 나옴** — 가려도 잃는 정보 없음을 확인.

```
 ┌──────────────────────────┐
 │ 2 11:30 이치란 라멘  🍜맛집│
 │ 3  —   긴자 쇼핑    🛍쇼핑│
 │                     ( ⚡ ) │ ← 스크롤 중: 작고 흐리게
 ├──────────────────────────┤
 │ 일정  장소  예약  준비     │
 └──────────────────────────┘
```
- 완료 조건: 360·412px에서 일정·마이·예약·준비 화면 끝까지 스크롤했을 때 버튼에 가려 못 누르는 요소 없음 (E2E: 버튼 영역과 겹치는 버튼·링크 검사)

### A2. 로그인 필수 이후 안내 문구 정리

**지금**: 장소 찾기·AI 추천·공유 시트·마이 계정 카드에 "로그인하면 …" + [로그인].
로그인 필수가 된 뒤 이 화면이 보이는 경우는 **로그인했던 기기가 서버에 닿지 않을 때**(홈 PC 꺼짐·오프라인) 뿐.

**바꿀 것**: `status === 'offline'`일 때 공통 안내 부품 `ServerOfflineNotice` 하나로
> 🔌 지금은 서버에 연결할 수 없어요. 일정·예약·준비물은 그대로 볼 수 있고, 연결되면 다시 쓸 수 있어요. [다시 시도]

- `status === 'anon'`이면 AuthGate가 이미 로그인 화면을 보이므로 각 화면의 로그인 버튼은 지운다
- 완료 조건: `rg "needLogin"` 결과 0 (i18n 키 정리 포함)

### A3. 개발용 화면은 운영에서 막기

- `router.tsx`의 `dev/*` 경로를 `import.meta.env.DEV`일 때만 등록. 운영에서 관리자에게 필요한 것(AI 수집 원자료 보기)은 **마이 → 관리자 → AI 점검**으로 옮기고 `requireAdmin`
- 서버 `/api/v1/ai/collect`도 관리자만
- 완료 조건: 운영 빌드에서 `/dev/ai` → 없는 화면, 일반 사용자의 collect 호출 → 403

### A4. 모든 화면에 제목(h1)

- `NotFoundPage`, 보기 전용 링크의 "없거나 꺼진 링크" 화면에 `TopBar`(h1) 추가
- E2E 접근성 점검(`a11y.spec.ts`) 대상에 두 화면 추가: "h1이 정확히 하나"

### B1. 여행 전 홈 — "준비 현황"

**지금**: D-day 카드 하나.

**바꿀 것**: D-day 카드 아래에 **다가오는 여행 1개 기준** 준비 카드 묶음 (여행 시작 30일 전부터, 없으면 지금처럼)

```
 ┌ D-3  도쿄 가을여행 ──────────────┐
 │ 10.27 – 10.31 · 4박 5일          │
 └──────────────────────────────────┘
 준비 현황
 ┌────────────┐ ┌────────────┐
 │ 🧳 준비물   │ │ 🎫 예약     │
 │ 12/30 ▓▓░░ │ │ 항공 1·숙소0│ ← 숙소 0이면 주황 점
 └────────────┘ └────────────┘
 ┌────────────┐ ┌────────────┐
 │ ☀️ 날씨     │ │ 💴 환율     │
 │ 첫날 18°/11°│ │ ¥100=912원 │
 └────────────┘ └────────────┘
 ┌──────────────────────────────────┐
```

- 각 카드는 그 화면으로 이동 (준비 탭·예약 탭·여행 달력·환율·AI)
- 데이터: 모두 **기기 DB와 이미 받아 둔 값**(날씨·환율 저장본)만 — 새 외부 호출 없음. 날씨는 출발 16일 안일 때만
- "할 일" 알림 규칙(작은 주황 점): 숙소 예약 0개 / 준비물 0개 / 출발 3일 전인데 할 일 남음
- 첫 화면 크기: 카드 묶음은 `lazy` (홈 첫 그림은 D-day 카드만)
- 완료 조건: 샘플 여행으로 4개 카드 표시, 각 카드 이동 E2E

### B2. 여행 중 홈 — "지금·다음"

**지금**: 다음 일정·숙소 길찾기 등 일부 있음 (HomePage).

**바꿀 것**
- 맨 위 **"다음 일정" 큰 카드**: 남은 시간("35분 뒤"), 장소, [길찾기] [주소 복사] — 3초 규칙
- 그 아래 **오늘 타임라인**(지난 일정은 흐리게, 지금 시각 선)
- 오늘 숙소 카드: 체크인 시간·주소·[숙소로 길찾기]
- 현지 시각(실험실 "현지 시각" 정식 반영 여부는 실험실 결과로)
- 완료 조건: 여행 중으로 시간을 맞춘 E2E에서 다음 일정·남은 시간 표시

### C1. 빈 날 접기

- 일정이 없는 날은 **한 줄**: `3일차 10.29 (목) · 일정 없음  [+ 추가]`
- 연속된 빈 날 3개 이상이면 `4~5일차 일정 없음`으로 묶고 누르면 펼침
- 하루 보기(Day 칩 선택)에서는 지금처럼 크게
- 완료 조건: 샘플 여행(5일 중 3일 빈 날) 전체 보기 높이 40% 이상 감소

### C2. 날짜 칩과 목록 연동

- 전체 보기에서 스크롤하면 **지금 화면 맨 위에 있는 날의 칩**에 표시(밑줄) + 칩 줄이 그 칩으로 가로 스크롤
- 칩을 누르면: 지금처럼 하루만 보기 (변경 없음). 길게 누르면 전체 보기에서 그 날로 스크롤 (선택)
- 구현: `IntersectionObserver` (라이브러리 없음)

### C3. 일정 사이 이동 정보 (실험실 → 정식)

- 실험실 `legDistance`의 사용 결과를 보고 정식화. 정식이면: 직선거리 + **설정의 기본 이동수단 기준 대략 시간**(도보 4.5km/h, 대중교통·자동차는 표시하지 않고 [길찾기]만)
- 같은 장소·좌표 없음이면 줄을 그리지 않음

### C4. 길게 눌러 편집 (실험실)

- 일정 줄을 0.5초 누르면 편집 모드로 들어가면서 그 줄을 집은 상태 → 끌어 놓기
- 편집 버튼은 그대로 둠 (발견하기 쉬움)
- 위험: 스크롤과 충돌 → 실험실에서 실제 휴대폰으로 확인 후 정식

### C5. 날짜 좌우 넘기기 (실험실)

- 하루 보기에서 목록을 좌우로 밀면 이전·다음 날 (지도 크게 보기 카드 넘기기와 같은 손동작)
- 위험: 가로 스크롤 요소(칩 줄)와 충돌 → 칩 줄 영역은 제외

| 숙소 | 체크인·체크아웃, 주소 | 길찾기·주소 복사·예약 보기·편집 | — |
| 메모 | 메모 내용 | 편집 | 길찾기·지도 |

- 꺼진(누를 수 없는) 버튼은 보이지 않게 — 지금 [주소 복사]가 흐리게 남는 문제
- 완료 조건: 항공 일정 상세에 "주소가 없어요"가 나오지 않음

### D2. 예약과 연결

- 예약에서 자동으로 생긴 일정(항공·숙소·식당)은 상세에 **예약 카드 요약**(예약번호 [복사], 탑승 시각, 좌석 등 저장된 항목)
- 연결 키: 이미 일정 화면에 예약 줄이 표시되는 규칙(`bookingRowsForDay`)을 그대로 사용 — 새 데이터 없음

### E1. 내 여행 카드

```
 ┌──────────────────────────────────┐
 │ 🗼  도쿄 가을여행          ⋯     │
 │     🇯🇵 10.27 – 10.31 · 4박 5일   │
 │     D-3 · 일정 6 · 준비물 12/30   │
 └──────────────────────────────────┘
 지난 여행 (3) ▾   ← 기본 접힘
```
- 나라 국기(이미 있는 국기 글꼴), 일정 수·준비물 진행
- 함께 쓰는 여행이면 멤버 수 아이콘(👥 3) — 보기 전용이면 "보기만"
- 지난 여행은 접힌 묶음

### E2. 저장한 장소

- 도시별 묶음(이미 `cityTag` 있음), 묶음마다 [지도에서 보기](지도 크게 보기 화면 재사용), [여행에 담기]

---

### F1. 동기화 상태 아이콘

- 여행 헤더 오른쪽 ⋯ 왼쪽에 작은 아이콘 하나: ✓(저장됨) / ↻(올리는 중) / ☁̸(오프라인, 기기에 저장됨)
- 누르면 한 줄 설명 토스트 ("이 기기에 저장됐어요. 연결되면 올려요")
- 데이터: `useSync`(이미 있음)

### F2. 오프라인 띠

- `navigator.onLine === false`면 화면 맨 위 얇은 띠 "오프라인 — 저장은 이 기기에, 연결되면 올려요"
- 다시 연결되면 "다시 연결됐어요" 2초 뒤 사라짐

### F3. 뼈대 화면

- 일정·예약·준비 화면에서 기기 DB를 읽는 짧은 순간 `null`(빈 화면) 대신 회색 줄 3개
- 공통 부품 `Skeleton` (CSS만)

---

### G1. 첫 로그인 안내

- 닉네임 정하기(이미 있음) → **여행이 없으면** "첫 여행 만들기" 큰 버튼 + "샘플 여행으로 둘러보기"(개발용 샘플 생성 재사용, 운영에서도 사용자용으로) → ⚡ 버튼에 말풍선 한 번 ("자주 쓰는 기능은 여기")
- 한 번 본 안내는 기기에 기록(`tp-onboarded`)

```
 [계정 카드: 닉네임 ✏ · 로그인 방법 · 동기화 상태]
```

### I1. 다크 모드 대비

- 보조 문구(`text-fg-muted`)·비활성 버튼·Day 색 배지 위 흰 글자의 대비를 자동 검사: E2E에서 주요 화면 다크 모드로 axe 계열 대비 검사 대신 **토큰 값으로 계산하는 단위 테스트**(새 의존성 없이 WCAG 대비 공식)
- 4.5:1 미만 토큰은 값 조정

### I2~I4 (실험실)

- I2 시트 높이: 손잡이를 끌어 반·전체 (지금은 내용 높이). Radix Dialog 위에 직접 구현
- I3 당겨서 동기화: 목록 맨 위에서 아래로 당기면 `syncNow()`
- I4 전환 애니메이션: View Transitions API(지원 브라우저만, 없으면 그대로) — 라이브러리 없음

## 5. 테스트·확인 방법

- **화면 캡처 비교**: Playwright로 주요 12개 화면을 라이트·다크, 360·412px로 찍어 `docs/design/screens/`에 단계 전후 비교 (저장소에는 최신본만)
- **겹침 검사(A1)**: 각 화면에서 ⚡ 버튼 사각형과 겹치는 누를 수 있는 요소가 없는지 E2E
- **접근성**: 기존 `a11y.spec.ts`(이름 없는 버튼·라벨·h1) 대상 화면 확대
- **크기**: 첫 화면 합계 300KB 안 (지금 174KB) — 새 홈 카드·안내는 지연 로딩
- **실기기**: 실험실 항목(C4·C5·I2·I3)은 아이폰·안드로이드에서 사용자 확인 후 정식

## 6. 결정이 필요한 것 (사용자)

1. **A1 기본 위치**: ⚡ 버튼 처음 자리를 "하단 탭 바로 위 오른쪽"으로 옮길까요? (이미 옮긴 위치는 유지)
2. **B1 준비 현황**: 홈에 보여 줄 카드 4개(준비물·예약·날씨·환율) + AI 추천 버튼 — 빼거나 더할 것?
3. **G1 샘플 여행**: 처음 쓰는 사람에게 "샘플 여행으로 둘러보기"를 보여 줄까요?
4. **실험실 후보**: C4 길게 눌러 편집, C5 날짜 좌우 넘기기, I2 시트 높이, I3 당겨서 동기화, I4 전환 애니메이션 — 넣을 것 고르기
