# 15. 단계별 구현 계획

- 원칙: **한 단계 = 한 세션(대화)에서 끝나는 크기**. 단계가 끝날 때마다 사용자가 직접 확인 → 수정 → 승인 → 커밋 → 다음 단계.
- 진행 상황은 루트의 `PROGRESS.md`에 기록한다. 새 세션은 `CLAUDE.md` → `PROGRESS.md` → 해당 단계의 관련 문서만 읽고 시작한다 (토큰 절약).

## 진행 방식 (매 단계 공통)
```
① 사용자: "N단계 진행해줘"
② Claude: PROGRESS.md·관련 문서 확인 → 이번 단계 작업 목록 3~6줄로 먼저 보여줌 → 구현
③ Claude: lint · typecheck · test 결과 + "이렇게 확인해 보세요" 안내 (실행 명령, 볼 화면, 눌러볼 것)
④ 사용자: 확인 → 수정 요청 (같은 단계 안에서 바로 반영, 반복)
⑤ 사용자: "OK" → Claude: PROGRESS.md 갱신 + 커밋 → 다음 단계 예고
```
- 단계 중 설계와 다른 결정이 생기면 `08-open-decisions.md`/ADR에 반영 후 진행.
- 한 세션에서 끝나지 않으면 PROGRESS.md에 "어디까지 했는지"를 적고 끊는다.
- **토큰 절약 팁**: 단계가 끝나면 `/clear`로 대화를 비우고 새로 시작해도 된다 (PROGRESS.md가 이어받음).

## 3부. 지도 · 장소 — 17~18단계
| 단계 | 내용 | 사용자 확인 방법 | 필요한 외부 준비 |
|---|---|---|---|
| **17** | 일정 화면 지도(S-10 상단): 네이버/구글 지도 전환, 일차별 색 핀·순서선, 핀↔목록 연동, 오프라인 대체 화면 | 도쿄 여행=구글, 제주 여행=네이버 지도로 핀 표시 | Google Maps JS 키, 네이버 Maps 키 (도메인 제한) |
| **18** | 장소 검색 서버 프록시 + 장소 찾기(S-14: 카테고리·평점·리뷰 수 필터) + 장소 상세(S-15: 리뷰) + 일정에 담기 + 저장 탭(S-04) + 하루 이용 한도 | "신주쿠 라멘 ⭐4.0+ 리뷰100+" 검색 → 담기 → 일정에 표시 | Google Cloud 결제·예산 알림, Places 서버 키, 네이버 검색 API |

> **18단계 추가 요구사항 (2026-10-22 사용자 요청)** — 일정 입력(S-11)의 장소 칸:
> - 입력하면 Google·네이버 검색 결과 중 **유사도 높은 순 드롭다운** (제목 + 아래 작은 주소, 출처 표시 G/N, 같은 장소는 하나로)
> - 각 항목 **오른쪽에 지도 버튼** → 그 장소를 지도에서 열기 (17단계 앱 안 지도 / 외부 지도 앱)
> - 고르면 이름·주소·좌표 저장 → 네이버·카카오 길찾기도 바로 경로로
> - **영업일·영업시간** 참고 표시("오늘 10:00–22:00 · 월요일 휴무"), 입력한 시간이 영업시간 밖이면 경고
> - 출처 확인: 영업시간·평점은 **Google Places만** 제공(네이버 검색 API에는 없음). Google 약관상 저장하지 않고 볼 때마다 조회 → 오프라인에서는 미표시

## 순서를 이렇게 정한 이유
1. **1부만으로도 쓸 수 있는 앱**이 나온다 → 서버·외부 키 없이 빠르게 화면을 보며 디자인·사용성을 다듬을 수 있다.
2. 외부 계정·비용이 드는 작업(도메인, 지도·장소 API, AI)을 **필요해지는 단계까지 미룬다**.
3. 동기화(15)를 지도(17)보다 먼저 하는 이유: 데이터 구조가 굳기 전에 동기화 메타 필드를 검증해야 나중에 고칠 일이 적다.
4. AI 추천은 장소 검색(18)의 Google 검증 코드를 재사용하므로 그 뒤에 둔다.
